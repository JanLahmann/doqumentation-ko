QCSC-Prefect로 양자 중심 슈퍼컴퓨팅 워크플로 관리

사용량 추정: IBM Quantum® Heron r2 프로세서에서 QPU 시간 30초. 이 추정에는 대기열 시간과 고전 처리가 포함되지 않습니다. 실제 실행 시간은 다를 수 있습니다.

학습 목표​

  • Prefect Cloud에서 Qiskit 패턴 단계마다 작업 하나씩으로 양자 중심 슈퍼컴퓨팅(QCSC) 워크플로를 추적합니다.

  • 워크플로를 역할별로 구성합니다. 실행 매개변수는 Prefect Cloud 실행 양식에서, 고성능 컴퓨팅(HPC)과 양자 처리 장치(QPU) 설정은 Prefect 블록에서 지정합니다.

  • 실패한 실행을 QPU 작업을 반복하지 않고 재개하고, 한 실행의 샘플을 새 실행에서 재사용합니다.

사전 준비 사항​

  • Slurm 클러스터에 QCSC-Prefect 설정하기: Slurm 로그인 노드, Python 환경, IBM Quantum 자격 증명을 준비합니다.

  • 화학 해밀토니안의 샘플 기반 양자 대각화: 알고리즘을 설명합니다.

배경​

QCSC 워크플로는 QPU와 HPC 시스템을 하나의 머신처럼 실행합니다. QCSC-Prefect는 Prefect에서 QCSC 워크플로를 실행하며, 추적 가능하고 구성 가능하며 재개 가능하게 유지합니다.

이 튜토리얼은 N2_22​ 분자의 샘플 기반 양자 대각화(SQD)로 이러한 기능을 보여 줍니다. Quantum Resource Management Interface (QRMI)가 Slurm 작업 안에서 회로를 샘플링합니다. Fulqrum 고유값 풀이기는 샘플링된 부분공간을 다른 Slurm 작업들에서 대각화합니다. 하나의 Prefect Cloud 배포가 이 둘을 모두 실행합니다.

QCSC-Prefect는 다음 프로젝트와 같은 대규모 QCSC 워크로드도 실행합니다.

  • 12,000개가 넘는 원자로 이루어진 단백질-리간드 복합체 연구에서 QCSC-Prefect를 사용했습니다. 156큐비트 IBM Quantum 프로세서 두 대에서 최대 94큐비트로 양자 임베딩 조각을 샘플링했고, Fugaku, Miyabi-G, ROQUO 슈퍼컴퓨터에서 조각 부분공간을 대각화했습니다 [1].

  • 철-황 클러스터 연구에서는 36개 오비탈(72큐비트)과 최대 3×10103 \times 10^{10}3×1010 차원의 부분공간을 가진 확장 QCSC-Prefect SQD 워크플로를 Fugaku, Miyabi, ROQUO 슈퍼컴퓨터에서 실행했습니다 [2].

QCSC 워크플로의 과제​

SQD 워크플로는 QCSC 워크로드의 전형적인 예입니다. QCSC-Prefect는 다음 표와 같이 각 과제에 하나의 기능으로 대응합니다.

과제QCSC-Prefect 기능
여러 자원에 걸쳐 있습니다. 한 Slurm 작업이 QPU를 점유하고, 이후 여러 Slurm 작업이 라운드마다 부분공간을 대각화합니다.추적 가능한 워크플로
과학, 회로, 클러스터 등 여러 수준에 많은 매개변수가 있으며, 자격 증명은 그 어디에도 들어가면 안 됩니다.구성 가능한 매개변수
길고, 시간 제한, 노드 장애, 긴 QPU 대기열 등 어디서든 실패할 수 있습니다. 대비하지 않으면 후반의 실패가 QPU에서 다시 샘플링해야 함을 뜻합니다.재개 가능한 실행

QCSC-Prefect의 Qiskit 패턴 단계별 설명의 각 단계는 QCSC-Prefect가 해당 단계를 어떻게 추적, 구성, 재개하는지 보여 주는 상자로 끝납니다.

추적 가능한 워크플로​

Prefect flow는 task로 구성된 Python 함수입니다. QCSC-Prefect는 Qiskit 패턴의 각 단계(Map, Optimize, Execute, Postprocess)를 하나의 task로 만듭니다. 각 실행마다 Prefect Cloud는 다음 정보를 보여 줍니다.

  • 한 task가 결과를 다른 task에 넘길 때마다 화살표로 표시되는 task 그래프.

  • 각 task의 상태, 입력, 로그, 소요 시간. 단계 태그 map, optimize, execute, post-process로 필터링할 수 있습니다.

  • 아티팩트: task가 게시하는 표와 링크로, 샘플의 출처나 각 부분공간의 에너지 등이 있습니다.

워크플로 호스트는 작업을 제출하고 모니터링하기만 합니다. 계산 집약적인 작업은 다음 이미지와 같이 Slurm 작업으로 실행됩니다.

구성 가능한 매개변수​

QCSC-Prefect는 다음 표와 같이 설정 종류마다 별도의 위치에 보관합니다.

종류예시변경 시점위치
실행 매개변수분자, 샷 수, 부분공간 차원매 실행단계별로 그룹화된 Prefect Cloud 실행 양식
블록파티션, 월타임, 스레드, 실행 파일 경로, QPU 자원클러스터별한 번 생성하는 Prefect 블록
자격 증명Prefect API 키, IBM Quantum API 키드물게워크플로 호스트의 Prefect Cloud 로그인, 그리고 클러스터의 QRMI(qcsc-qrmi login). 둘 다 설정 가이드에서 설정합니다

블록은 다음 표의 세 계층으로 각 작업을 기술합니다.

블록지정하는 것내용
CommandBlock무엇을 실행하는지실행 파일과 기본 인수
ExecutionProfileBlock어떻게 실행하는지노드, 스레드, 월타임, 런처, 모듈, 환경
HPCProfileBlock어디서 실행하는지스케줄러, 파티션, 계정, 해당 시스템에서 각 실행 파일의 경로

flow는 실행할 때 이름으로 블록을 불러오므로, 블록을 바꿔도 flow와 실행 매개변수는 그대로입니다.

재개 가능한 실행​

Prefect는 처음 세 단계의 결과를 flow 실행과 함께 저장합니다. 이후 task가 실패하면 flow 실행에서 Retry를 선택해 저장된 결과를 재사용하고 실패한 부분만 다시 실행합니다. 다음 이미지를 참고하세요.

Execute 단계가 샘플의 위치를 기록하므로, 새 실행은 샘플링하는 대신 이전 실행의 샘플을 불러올 수도 있습니다.

SQD 개요​

SQD는 결합 클러스터 단일 및 이중(CCSD) 진폭으로 만든 국소 유니터리 클러스터 Jastrow(LUCJ) 회로에서 비트열을 샘플링하고, 잡음으로 손상된 비트열을 바로잡고(구성 복구), 샘플링된 구성이 span하는 부분공간에서 해밀토니안을 대각화합니다 [3]. 알고리즘은 SQD 튜토리얼에서 설명합니다. QCSC-Prefect에서 SQD는 flow sqd이며, task 그래프는 다음과 같습니다.

단계Task다른 task로부터의 입력
Mapcompute_molecular_integrals없음
Optimizeget_lucj_paramsMap의 적분
Executequantum_sampling, 그 안에 build_lucj_circuitOptimize의 LUCJ 매개변수
Postprocesssqd_loopMap의 적분, Execute의 샘플

실행이 샘플을 재사용하면 load_qrmi_result(IBM Quantum Platform의 샘플인 경우 load_runtime_job)가 get_lucj_params와 quantum_sampling을 모두 대체하므로 실행에 Optimize task가 없습니다. 무작위 모드(Quantum Source를 random으로 설정)에서는 Optimize와 Execute task가 없고 Map이 sqd_loop에 직접 입력을 전달합니다.

예제는 6-31G 기저에서 결합 길이 1.1 A˚\AAA˚의 N2_22​이며, 두 개의 1s 코어 오비탈은 고정했습니다. 그러면 5개의 α\alphaα 전자와 5개의 β\betaβ 전자를 가진 16개의 공간 오비탈이 남으며, 이는 32큐비트 회로에 해당합니다.

요구 사항​

이 노트북의 코드 셀을 실행하려면 노트북 커널에 다음 패키지를 설치하세요.

  • 시각화를 지원하는 Qiskit SDK v2.0 이상.

  • Qiskit Runtime v0.40 이상(pip install qiskit-ibm-runtime).

  • SQD Qiskit 애드온 v0.14 이상(pip install qiskit-addon-sqd).

  • ffsim v0.0.75 이상(pip install ffsim).

  • Fulqrum v1.0 이상(Fulqrum 설치 가이드 참조).

이 노트북의 3단계는 Qiskit Runtime으로 샘플링하므로, 로그인 자격 증명 저장에 설명된 대로 노트북을 실행하는 컴퓨터에 IBM Quantum 계정이 저장되어 있어야 합니다.

참고

QCSC-Prefect 워크플로는 이 노트북이 아니라 Slurm이 관리하는 클러스터에서 실행됩니다. 실행하기 전에 Slurm 클러스터에 QCSC-Prefect 설정하기를 완료하세요. 이 가이드는 다음 항목을 제공합니다.

  • $QCSC_PREFECT(~/qcsc-prefect)의 QCSC-Prefect 체크아웃과 $QCSC_WORK_DIR(/shared/work/qcsc-prefect)의 작업 디렉터리. 둘 다 컴퓨트 노드가 공유하는 스토리지에 있어야 합니다.

  • 워크플로 호스트인 Slurm 로그인 노드에는 QCSC-Prefect 패키지가 설치된 환경 ~/venv/qcsc-host와 Prefect Cloud 로그인이 있어야 합니다.

  • QRMI와 그 SPANK 플러그인이 있는 클러스터에서 qcsc-qrmi login으로 저장한 IBM Quantum 자격 증명과 qrmi-runtime 블록.

  • 컴퓨트 노드에는 QRMI, 그 task_runner, qcsc-prefect-qiskit가 설치된 환경 ~/venv/qcsc-node가 있어야 합니다.

다음 단계를 한 번 실행하세요. 각 단계에는 실행할 노드가 명시되어 있습니다.

워크플로 호스트에 SQD 워크플로 설치하기​

설정 가이드의 변수를 설정하고 ~/venv/qcsc-host를 활성화한 다음, SQD 워크플로와 Fulqrum 통합을 설치합니다.

# Run in a terminal on the workflow host.
# Optional if your ~/.bashrc sets the two variables
export QCSC_PREFECT="$HOME/qcsc-prefect"
export QCSC_WORK_DIR="/shared/work/qcsc-prefect"

source ~/venv/qcsc-host/bin/activate
cd "$QCSC_PREFECT"
uv pip install --no-deps -e packages/qcsc-prefect-fulqrum
uv pip install -e algorithms/qcsc_workflow_utility
uv pip install -e algorithms/open_loop/sqd
which sqd-create-blocks sqd-deploy

컴퓨트 노드에 Fulqrum 풀이기 설치하기​

컴퓨트 노드에서 셸을 엽니다. srun은 워크플로 호스트 셸의 변수를 컴퓨트 노드에 전달합니다.

# Run in a terminal on the workflow host.
srun -N1 --pty bash

QRMI 워커는 Qiskit만 임포트하는 SQD 트랜spile 훅으로 컴퓨트 노드에서 회로를 트랜spile합니다. 이 훅을 ~/venv/qcsc-node에 추가하고 임포트를 확인하세요. 임포트에 성공하면 python 명령은 아무것도 출력하지 않습니다.

# Run in the shell on the compute node.
source ~/venv/qcsc-node/bin/activate
cd "$QCSC_PREFECT"
uv pip install --no-deps -e algorithms/open_loop/sqd
python -c "import qrmi, qcsc_prefect.integrations.qiskit.qrmi.worker, sqd_common.transpile"

Fulqrum과 qcsc-fulqrum-solve를 packages/qcsc-prefect-fulqrum/native/fulqrum 환경에 따로 빌드합니다. 빌드에는 OpenMP를 지원하는 C++ 컴파일러가 필요합니다. FULQRUM_WITH_PRIMME=1은 PRIMME 고유값 풀이기도 빌드하며, 이를 위해 C 컴파일러, Python 헤더, pkg-config, 그리고 .pc 파일이 있는 BLAS 및 LAPACK 라이브러리가 필요합니다.

# Run in the shell on the compute node.
cd "$QCSC_PREFECT"
FULQRUM_WITH_PRIMME=1 bash packages/qcsc-prefect-fulqrum/native/build_fulqrum.sh
realpath packages/qcsc-prefect-fulqrum/native/fulqrum/bin/qcsc-fulqrum-solve
exit

풀이기 블록이 이 경로를 가리키므로 출력된 경로를 기록해 두세요. exit는 워크플로 호스트로 돌아갑니다. 빌드 옵션은 Fulqrum 통합을 참조하세요.

워크플로 호스트에서 Prefect 블록 구성 및 생성하기​

예제 구성을 복사합니다.

# Run in a terminal on the workflow host.
cd "$QCSC_PREFECT"
cp algorithms/open_loop/sqd/sqd_blocks.example.toml \
   algorithms/open_loop/sqd/sqd_blocks.toml

다음 표와 같이 sqd_blocks.toml 상단의 설정을 편집합니다.

파일을 편집할 때 다음 사항에 유의하세요.

  • 이 파일은 환경 변수를 확장하지 않으므로 경로를 전부 풀어서 쓰세요. ~ 문자는 사용할 수 있습니다. python_executable 같은 모든 최상위 키는 첫 번째 테이블 헤더 앞에 두세요.

  • qrmi-runtime 블록이 인스턴스와 QPU를 제공하므로 [qrmi] 테이블은 변경할 필요가 없습니다. 백엔드를 재정의할 때만 resource를 설정하세요. 자격 증명은 이 파일이 아니라 qrmi_config.json에 보관됩니다.

  • slurm 프로파일은 일반적인 Slurm 클러스터의 스케줄러 및 자원 설정을 담고 있으며, 파일의 모든 키가 이를 재정의합니다. 주석 처리된 [sqd_advanced] 테이블은 sqd-advanced-settings 블록을, 주석 처리된 [advanced] 테이블은 블록 이름과 타임아웃을 설정하고, 각 풀이기의 테이블에는 해당 풀이기의 튜닝 값이 들어 있습니다. 풀이기 작업의 노드, 랭크, 스레드를 선택하려면 HPC 자원에 맞게 SQD 대각화 크기 조정하기를 참조하세요.

  • QRMI 작업과 각 solver 작업의 walltime은 12시간(#SBATCH --time)이며, 플로우는 각 작업을 최대 13시간(timeout_seconds = 46800) 동안 기다립니다. walltime을 변경하려면 solver 작업의 경우 파일 상단에서 walltime을 설정하고, QRMI 작업의 경우 [qrmi] 테이블에서 설정하세요. 예를 들어 walltime = "02:00:00"처럼 지정합니다. walltime이 더 짧으면 바쁜 클러스터에서 더 빨리 시작할 수 있습니다.

1단계: 고전 입력을 양자 문제로 매핑하기​

Map 단계(워크플로의 task compute_molecular_integrals)는 분자를 이후 모든 단계의 입력으로 바꿉니다. 제한 Hartree-Fock(RHF)가 분자 오비탈을 제공하고, 활성 공간 적분에서는 고정된 두 1s 코어를 제외합니다. CCSD는 ansatz의 t2t_2t2​ 진폭을 제공하고, 그 밀도 행렬은 구성 복구를 시작하는 오비탈 점유수를 제공합니다. CCSD는 매번 이전 진폭에서 시작해 CCSD_MAXITER번 반복하므로, 결과가 첫 반복의 DIIS 이력에 의존하지 않습니다. 이 노트북은 4번 반복하고, 워크플로는 10번 반복합니다.

ATOM = "N 0 0 0; N 0 0 1.1"
BASIS = "6-31g"
N_FROZEN = 2
CCSD_MAXITER = 4

mol = pyscf.gto.M(atom=ATOM, basis=BASIS, symmetry=False, verbose=0)
mf = scf.RHF(mol).run()
norb = mol.nao_nr() - N_FROZEN
nelec = (mol.nelec[0] - N_FROZEN, mol.nelec[1] - N_FROZEN)

# Active-space Hamiltonian with the 1s cores frozen
cas = mcscf.CASCI(mf, ncas=norb, nelecas=nelec)
one_body_tensor, core_energy = cas.get_h1eff()
two_body_tensor = ao2mo.restore(1, cas.get_h2eff(), norb)

# CCSD, iterated from the previous amplitudes
ccsd = cc.CCSD(mf, frozen=N_FROZEN)
eris = ccsd.ao2mo()
ccsd.kernel(eris=eris)
for _ in range(CCSD_MAXITER - 1):
    ccsd.kernel(ccsd.t1, ccsd.t2, eris=eris)
t2 = ccsd.t2

occupancies = np.diag(ccsd.make_rdm1())[N_FROZEN:] / 2
initial_occupancies = (occupancies, occupancies)

print(f"norb = {norb}, nelec = {nelec}")
print(f"E(RHF)  = {mf.e_tot:.8f} Ha")
print(f"E(CCSD) = {ccsd.e_tot:.8f} Ha")
norb = 16, nelec = (5, 5)
E(RHF)  = -108.86761837 Ha
E(CCSD) = -109.09392115 Ha

2단계: 양자 하드웨어 실행을 위한 문제 최적화하기​

Optimize 단계(워크플로의 task get_lucj_params)는 회로가 만들어지기 전에 ansatz를 QPU에 맞춥니다. ffsim은 t2t_2t2​로부터, heavy-hex 격자가 SWAP 게이트 없이 실행할 수 있는 상호작용만으로 LUCJ 연산자를 만듭니다. 이는 이웃한 오비탈의 같은 스핀 쌍과 네 번째 오비탈마다의 반대 스핀 쌍이며, heavy-hex(Heron) 프로세서에서는 최대 다섯 개입니다. 그런 다음 ffsim은 한 층이 t2t_2t2​를 더 가깝게 재현하도록 연산자를 압축합니다(optimize=True, 워크플로에서는 기본값으로 켜져 있음).

N_REPS = 1

pairs_aa = [(p, p + 1) for p in range(norb - 1)]
pairs_ab = [(p, p) for p in range(0, norb, 4)][:5]

lucj_op = ffsim.UCJOpSpinBalanced.from_t_amplitudes(
    t2,
    n_reps=N_REPS,
    interaction_pairs=(pairs_aa, pairs_ab),
    optimize=True,
    options={"maxiter": 50},
)
n_params = ffsim.UCJOpSpinBalanced.n_params(
    norb, N_REPS, interaction_pairs=(pairs_aa, pairs_ab)
)

print(f"Opposite-spin pairs: {pairs_ab}")
print(f"Ansatz parameters: {n_params}")

def correct_electron_fraction(bool_array):
    """Fraction of the bitstrings with the correct numbers of alpha and beta electrons."""
    # The right half of each bitstring is alpha, the left half is beta.
    n_alpha, n_beta = nelec
    valid = (bool_array[:, norb:].sum(axis=1) == n_alpha) & (
        bool_array[:, :norb].sum(axis=1) == n_beta
    )
    return valid.mean()

Execute가 회로를 만들고 트랜spile하는 이유

QRMI 워커는 QPU의 현재 Target에 맞춰 컴퓨트 노드에서 회로를 트랜spile하므로, 트랜spile은 QRMI Runtime이 담당합니다. 이러한 분리는 양자 저밀도 패리티 검사(LDPC) 오류 정정 회로의 트랜spile이 큰 워크로드인 내결함성 QCSC 시스템을 대비한 것입니다. 워크플로는 회로가 아니라 회로 매개변수를 캐시합니다. Map과 Optimize가 회로를 설계합니다. Map은 CCSD 진폭을 계산하고, Optimize는 ffsim.UCJOpSpinBalanced.from_t_amplitudes(optimize=True)로 LUCJ 연산자를 압축하며, 이는 현재 QPU용 트랜spile보다 오래 걸릴 수 있습니다. build_lucj_circuit과 트랜spiler는 이 매개변수를 ISA 회로로 인코딩할 뿐입니다. 이러한 분리는 기존 Qiskit 패턴과 다르며, QCSC 시스템에서 Qiskit 패턴이 어떤 모습일 수 있는지를 시사합니다.

4단계: 후처리하고 원하는 고전 형식으로 결과 반환하기​

Postprocess 단계(워크플로의 task sqd_loop)는 자체 일관성 구성 복구를 실행합니다. 각 라운드는 현재 오비탈 점유수로 샘플링된 비트열을 보정하고, 여러 구성 배치에서 해밀토니안을 대각화하며, 최상의 결과로 점유수를 갱신합니다. 다음 셀은 두 샘플 집합에 같은 설정으로 diagonalize_fermionic_hamiltonian을 실행합니다. 부분공간 차원은 워크플로의 1,000,000개 행렬식(스핀당 1,000개 문자열)입니다. 노트북은 라운드당 두 배치와 열 라운드를 사용하고, 워크플로는 네 배치와 다섯 라운드를 사용합니다. 워크플로와 같이 Fulqrum이 각 부분공간을 대각화합니다. sci_solver_from_integrals는 Fulqrum 해밀토니안을 한 번 만들고, 함수가 각 배치마다 호출하는 sci_solver를 반환합니다. SQD 튜토리얼에서처럼 TrimPolicy는 배치에서 가장 가중치가 큰 문자열을 하나의 부분공간으로 병합하고 대각화합니다. carryover_threshold를 넘는 문자열 중에서는 워크플로의 Carryover Fraction처럼 가장 가중치가 큰 절반(carryover_ratio=0.5)을 다음 라운드로 넘깁니다.

SUBSPACE_DIM = 1_000_000
NUM_BATCHES = 2
MAX_ITERATIONS = 10

policy = TrimPolicy(
    trim_ratio=0.8,
    carryover_threshold=1e-4,
    carryover_ratio=0.5,
)
sci_solver = sci_solver_from_integrals(one_body_tensor, two_body_tensor)

def run_sqd(bool_array, label):
    """Run SQD on the samples, and return the final energy and the energy of each round."""
    round_energies = []

    def callback(results):
        round_energies.append(
            min(result.energy for result in results) + core_energy
        )
        print(
            f"{label}, round {len(round_energies)}: {round_energies[-1]:.8f} Ha"
        )

    result = diagonalize_fermionic_hamiltonian(
        one_body_tensor,
        two_body_tensor,
        bool_array,
        samples_per_batch=1000,
        norb=norb,
        nelec=nelec,
        num_batches=NUM_BATCHES,
        max_iterations=MAX_ITERATIONS,
        policy=policy,
        sci_solver=sci_solver,
        symmetrize_spin=True,
        max_dim=int(np.sqrt(SUBSPACE_DIM)),
        initial_occupancies=initial_occupancies,
        callback=callback,
        seed=np.random.default_rng(24),
    )
    return result.energy + core_energy, round_energies

quantum_energy, quantum_round_energies = run_sqd(
    quantum_bool_array, "Quantum samples"
)
random_energy, random_round_energies = run_sqd(
    random_bool_array, "Random samples"
)
print(f"SQD energy with quantum samples: {quantum_energy:.8f} Ha")
print(f"SQD energy with random samples:  {random_energy:.8f} Ha")

QCSC-Prefect가 이 단계를 관리하는 방법

추적: task sqd_loop에는 post-process 태그가 있습니다. 샘플과 적분을 받으므로 그래프에서 두 개의 화살표가 들어갑니다. 각 배치는 FulqrumSolverJob 호출 하나로, Fulqrum을 실행하는 Slurm 작업 하나를 제출하는 solve_eigenstate task입니다. 한 라운드의 배치는 컴퓨트 노드에서 동시에 실행됩니다. sqd-configuration-recovery 아티팩트는 모든 라운드의 모든 부분공간의 에너지와 차원을 나열합니다.

구성: 실행 양식의 SQD 그룹에서 부분공간 차원, 배치 수, 라운드 수를 설정합니다. 실행 양식의 Solver Block Override(solver_block_ref)는 한 번의 실행에 한해 sqd-advanced-settings의 Solver Block을 대체하며, 예를 들어 DICE나 SBD 블록으로 바꿀 수 있습니다. 고유값 풀이기(PRIMME), 스레드, 월타임은 sqd-fulqrum-solver 블록과 그 실행 프로파일에 있습니다. flow는 어떤 단계보다 먼저 풀이기 블록을 불러오므로, 블록 이름이 잘못되면 QPU를 사용하기 전에 실행이 실패합니다.

재개: sqd_loop은 캐시되지 않지만 매 라운드 후에 풀이기의 work_dir 아래 sqd_checkpoints/<flow run id>/ckpt_t00_w0.npz에 체크포인트를 저장합니다. 체크포인트에는 다음 라운드의 시작점이 되는 점유수와 지금까지의 최상 에너지가 들어 있습니다. Retry하면 sqd_loop은 현재 블록으로 마지막으로 완료된 라운드 이후부터 계속합니다.

전체 워크플로 실행하기​

워크플로 호스트에서 Prefect 블록 구성 및 생성하기의 블록이 이미 클러스터와 QPU를 기술하므로, 실행에는 실행 매개변수만 있으면 됩니다.

선택 사항: 워크플로 재개 및 재사용​

실패한 실행을 재시도하고 그 샘플 재사용하기​

Retry: Max Iteration을 10으로 설정한 실행에서 5라운드에 풀이기 작업이 월타임에 도달해 sqd_loop이 실패했다고 가정합니다. Blocks 아래의 exec-sqd-fulqrum-slurm 블록에서 월타임을 늘린 다음, 실패한 flow 실행에서 Retry를 선택하세요. 재시도된 실행은 처음 세 단계의 저장된 결과를 불러오고 QPU 작업을 제출하지 않습니다. 새 월타임으로 sqd_loop만 다시 실행하며, 4라운드의 체크포인트에서 5라운드부터 시작합니다. 로그에는 다음 이미지와 같이 [ckpt] RESUME from …: completed 4 step(s)에 이어 SQD iteration 5/10이 표시됩니다.

Reuse: 이전 샘플을 지정하지 않으면 새 실행은 모든 것을 다시 계산합니다. 같은 샘플로 다른 부분공간 차원을 시험하려면 같은 매개변수로 사용자 지정 실행을 시작하고, Load from QRMI Job Directory(qrmi_result_dir)를 첫 실행의 sqd-sampling-source 아티팩트에 있는 작업 디렉터리로 설정한 다음 Subspace Dimension을 바꾸세요. 새 실행은 get_lucj_params와 quantum_sampling을 load_qrmi_result로 대체하며, 이 task는 샘플을 읽고 QPU에는 아무것도 제출하지 않습니다. 다시 불러올 때 적용되므로 sqd-advanced-settings의 Reset Mitigation은 첫 실행과 같아야 합니다. IQP로 얻은 샘플은 대신 Load from Qiskit Runtime Job ID(qiskit_runtime_job_id)를 설정하며, 이 경우 단계는 load_runtime_job입니다. 이 task는 Quantum Runtime Block (reload)(ibm-runner가 기본값)에 지정된 prefect-qiskit QuantumRuntime 블록의 자격 증명으로 작업을 읽습니다. 이 블록은 prefect block create quantum-runtime으로 한 번만 생성하세요.

더 많은 라운드로 복구 이어가기: 같은 매개변수로 사용자 지정 실행을 시작하고, Resume from Checkpoint(resume_checkpoint)를 첫 번째 실행의 sqd-checkpoint 아티팩트에 있는 경로로 설정한 다음 Max Iteration을 늘립니다. 새 실행은 저장된 점유수와 최적 에너지에서 시작하여 완료된 라운드 이후부터 이어집니다. 예를 들어 100라운드 중 32라운드가 완료된 체크포인트에서 Max Iteration을 200으로 설정하면 33/200 라운드부터 이어집니다. 새 실행은 해당 체크포인트를 읽고 자체 체크포인트를 기록하며, 다음 규칙이 적용됩니다.

  • 샘플, 분자, Subspace Dimension, Batch Number, 그리고 솔버 유형(솔버 블록의 fulqrum_solver_job 부분)은 첫 번째 실행과 일치해야 하므로, Reuse에서처럼 첫 번째 실행의 샘플을 재사용하세요.

  • 솔버 블록의 이름과 walltime 같은 작업 설정은 변경할 수 있습니다.

  • 일치해야 하는 설정이 다르면 솔버 작업이 실행되기 전에 실행이 실패하며 어떤 부분이 다른지 알려 줍니다.
