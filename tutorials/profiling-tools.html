실험을 프로파일링, 사용자 지정, 검사하는 도구

사용량 추정: Heron r2 프로세서에서 10분 (참고: 추정치일 뿐이며 실제 실행 시간은 다를 수 있습니다.)

양자 컴퓨터에서 좋은 결과를 얻으려면 잘 설계된 회로 이상의 것이 필요합니다. 장치의 현재 상태, 회로가 스케줄링되는 방식, 회로가 겪는 노이즈, 그리고 작업이 양자 처리 장치(QPU)에서 언제 어떻게 실행되는지가 모두 결과의 품질에 영향을 줍니다. Qiskit과 IBM Quantum® Compute Service는 이러한 정보를 보여 주는 개발자 도구를 계속 늘려 가고 있습니다. 이 도구들을 사용하면 전체 실험에 QPU 시간을 투입하기 전에 그 정보를 바탕으로 조치를 취할 수 있고, 완료된 실험을 디버깅할 수도 있습니다.

이 튜토리얼은 하나의 엔드투엔드 실험을 통해 일반적인 개발 워크플로의 각 단계에서 이 도구들을 어떻게 조합하는지 보여 줍니다. 모든 도구가 모든 실험에 유용한 것은 아니므로, 자신의 워크로드에 대해 가진 질문에 답해 주는 도구를 선택하세요.

워크플로는 다음과 같습니다.

  1. 선형 횡자기장 Ising 모델의 Trotter화된 시간 발전에 대한 미러 회로를 준비합니다.

  2. 노이즈 모델에 기반한 오류 완화 방법을 위해 설계된 대체 보정 데이터 세트를 가진 백엔드를 선택합니다.

  3. Transpiler가 레이아웃을 선택할 때 최신 장치 속성을 사용하도록 장치 벤치마킹 실험을 실행합니다.

  4. 스케줄링된 회로의 타이밍 정보를 검사합니다.

  5. 회로에 대한 Pauli-Lindblad 및 판독 노이즈 모델을 학습합니다.

  6. 노이즈 없는 시뮬레이션, 완화하지 않은 시뮬레이션, 완화한 로컬 시뮬레이션을 실행합니다. 노이즈가 있는 시뮬레이션은 학습된 노이즈 모델을 사용하여 선택한 오류 완화 방법으로 얼마나 개선될 수 있는지 보여 줍니다. 이 튜토리얼에서는 확률적 오류 상쇄(PEC)와 Twirled Readout Error eXtinction(TREX)을 사용합니다.

  7. QPU에서 실행하지 않고 사용량 추정치를 얻어, 예산에 맞도록 실험을 조정해야 하는지 확인합니다.

  8. 세션을 시작하고 보정을 트리거하여 실험이 가장 최근의 보정 데이터를 사용하도록 합니다.

  9. Estimator를 사용하여 QPU에서 실험을 실행하고, 하드웨어 결과를 시뮬레이션 미리 보기와 비교합니다.

  10. 실행 스팬을 검사하여 실행 그룹(청크) 사이에 큰 간격이 있는지 확인합니다.

1단계: 회로와 관측량 지정​

선형 횡자기장 Ising 모델의 Trotter화된 시간 발전에 대한 미러 회로를 준비합니다. 회로를 미러링하면 회로의 유니터리가 상쇄되어 항등 회로가 됩니다. 이상적인 출력은 모두 0인 상태이므로, 각 단일 큐비트 ZZZ 관측량의 이상적인 기댓값은 1입니다. 미러링은 회로 깊이도 두 배로 늘려 노이즈의 영향을 증폭합니다.

import numpy as np
from qiskit.circuit import QuantumCircuit
from qiskit.quantum_info import SparsePauliOp

def construct_ising_circuit(
    num_qubits: int,
    num_trotter_steps: int,
    rx_angle: float,
    barrier: bool = True,
) -> QuantumCircuit:
    circuit = QuantumCircuit(num_qubits)

    for _step in range(num_trotter_steps):
        circuit.rx(rx_angle, range(num_qubits))
        if barrier:
            circuit.barrier()
        for first_qubit in (1, 2):
            for idx in range(first_qubit, num_qubits, 2):
                # equivalent to Rzz(-pi/2):
                circuit.sdg([idx - 1, idx])
                circuit.cz(idx - 1, idx)
        if barrier:
            circuit.barrier()

    return circuit

def mirror_circuit(circuit: QuantumCircuit) -> QuantumCircuit:
    mirror_circ = circuit.copy_empty_like()
    mirror_circ.compose(circuit, inplace=True)
    mirror_circ.barrier()
    mirror_circ.compose(circuit.inverse(), inplace=True)
    mirror_circ.measure_active()
    return mirror_circ
num_qubits = 20
observables = [
    SparsePauliOp("I" * ((num_qubits - 1) - q) + "Z" + "I" * q)
    for q in range(num_qubits)
]

# Free parameters of the demonstration circuit: the number of Trotter steps
# sets the circuit depth, and rx_angle is the transverse-field rotation angle
# applied in each step (pi/4 makes the dynamics non-Clifford)
num_trotter_steps = 5
rx_angle = np.pi / 4

circuit = construct_ising_circuit(
    num_qubits, num_trotter_steps, rx_angle, barrier=False
)
mirrored_circuit = mirror_circuit(circuit)
mirrored_circuit.draw(
    "mpl", fold=-1, scale=0.3, idle_wires=False, measure_arrows=False
)

2.1 해당되는 경우 대체 보정 사용​

IBM®는 일반적인 사용 사례 전반에서 좋은 성능을 내도록 QPU를 주기적으로 보정합니다. 그러나 일부 워크로드는 매개변수를 다르게 조정한 명령어의 이점을 얻습니다. 자세한 내용은 특별히 보정된 명령어를 참조하세요.

이 튜토리얼은 slow_gates_ac라는 대체 보정 데이터 세트를 사용합니다. 이 보정에는 더 느린 cz 게이트가 들어 있으며, 2준위 시스템(TLS) 바이어스를 변조하여 시간에 따른 장치 오류를 안정화합니다. 이러한 변경은 학습된 노이즈 모델에 의존하는 오류 완화 방법에 도움이 됩니다. slow_gates_ac 보정은 Heron QPU에서만 사용할 수 있습니다. Nighthawk QPU에서 실행한다면 대신 slow_gates를 사용하세요.

from qiskit_ibm_runtime import QiskitRuntimeService

service = QiskitRuntimeService()
# Use slow_gates_ac because this tutorial uses a noise-learning-based mitigation method
backend = service.backend("ibm_kingston", calibration_id="slow_gates_ac")

2.2 실시간 장치 벤치마킹 실행​

트랜스파일의 가장 중요한 단계 중 하나는 레이아웃 선택으로, 회로의 가상 큐비트를 대상 장치의 물리 큐비트에 매핑합니다. 좋은 레이아웃은 필요한 SWAP 연산의 수를 최소화하고 회로를 성능이 가장 좋은 큐비트에 배치하므로, 초기 레이아웃의 품질이 결과의 품질에 크게 영향을 줄 수 있습니다.

모든 IBM QPU에서는 큐비트의 현재 성능, 즉 이완 시간(T1T_1T1​), 결맞음 시간(T2T_2T2​), 판독 오류, 1큐비트 및 2큐비트 게이트 오류를 보고하는 벤치마킹 루틴이 주기적으로 실행됩니다. Qiskit Transpiler는 레이아웃을 선택할 때 이 지표들을 사용합니다.

그러나 초전도 큐비트의 속성은 더 짧은 시간 척도에서 변동할 수 있으며, TLS라고 하는 일시적 결함이 보정 시점에는 성능이 좋았던 큐비트를 일시적으로 악화시킬 수 있습니다. Transpiler가 오래된 정보를 사용하면 최적의 레이아웃을 선택할 수 없습니다. 따라서 레이아웃을 선택하기 전에 QPU 시간을 일부 들여 장치의 특성을 파악하는 것이 가치 있을 수 있습니다.

2.4 회로 타이밍 시각화​

회로의 명령어 외에도, 큐비트의 유휴 시간이나 비효율적인 명령어 정렬을 찾기 위해 회로의 스케줄을 시각화하고 싶을 수 있습니다. 드라이런 모드를 사용하면 IBM Quantum Compute Service에서 가장 상세하고 정확한 타이밍 정보를 얻을 수 있습니다.

이 튜토리얼의 회로는 정적이므로 스케줄이 그다지 유익하지 않습니다. 회로와 백엔드 속성만으로도, 예를 들어 Qiskit에 내장된 타임라인 드로어를 사용하여 비슷한 타이밍 정보를 로컬에서 얻을 수 있습니다. 이 튜토리얼에서는 타이밍 정보를 요청하고 시각화하는 방법을 보여 주기 위해 이 단계를 포함했습니다. 서비스의 타이밍 정보는 동적 회로에서 가장 유용합니다. 동적 회로에는 회로 중간 측정, 조건부 연산, 피드포워드가 포함되며, 이로 인해 측정 결과 브로드캐스트나 분기 결정 같은 암묵적 연산이 추가됩니다. 이러한 연산의 타이밍은 회로와 백엔드 속성만으로는 알 수 없습니다.

3.2 TREX와 함께 PEC 적용​

특정 실험에 대해 비용과 정확도의 균형을 맞추는 오류 완화 방법을 선택하기는 어려울 수 있습니다. select-error-mitigation AI 에이전트 스킬을 사용하면 워크로드에 사용할 수 있는 방법들을 분석할 수 있습니다. 이 스킬은 각 방법이 선택되었는지와 그 이유를 설명하는 요약 보고서를 제공합니다.

자세한 내용은 Qiskit AI 스킬 GitHub 저장소를 참조하세요. 이 튜토리얼은 AI 에이전트 없이도 완료할 수 있도록 PEC와 TREX를 직접 사용합니다.

PEC는 관측량의 기댓값을 계산할 때 양자 노이즈를 완화하는 기법입니다. 이상적인 조건에서 PEC는 기댓값의 불편 추정치를 만들 수 있습니다. 2큐비트 게이트의 각 레이어의 노이즈를 학습한 다음, 평균적으로 그 노이즈의 역을 적용하는 회로 앙상블을 실행합니다. PEC는 Pauli 트월링을 사용하여 노이즈를 Pauli 채널로 맞추며, 이 채널은 효율적으로 학습하고 역변환할 수 있습니다.

실제로 PEC의 정확도는 학습된 노이즈 모델의 정확도를 넘지 못합니다. 희소 Pauli-Lindblad 모델에는 이웃한 큐비트의 1큐비트 및 2큐비트 오류 항만 포함되므로 멀리 떨어진 큐비트 사이의 크로스토크나 시간 상관 오류 같은 효과를 완전히 포착할 수 없습니다. 또한 장치 노이즈는 노이즈 학습과 실행 사이에 변동할 수 있습니다. PEC는 모델이 놓친 노이즈를 상쇄하지 못하며, 모델이 과대평가한 노이즈는 과도하게 보정합니다. 따라서 완화된 결과도 어느 방향으로든 이상적인 값에서 벗어날 수 있습니다.

TREX는 측정 오류를 완화하는 기법이며, Pauli 관측량의 기댓값을 추정할 때 유용합니다. 이 기법은 판독 오류 전이 행렬을 대각화하여 역변환하기 쉽게 만드는 측정 트월링에 의존합니다. TREX는 0 상태로 초기화된 트월링된 보정 회로를 측정하여 대각 노이즈 채널로부터 재조정 항을 학습합니다. Estimator 옵션을 설정하여 PEC와 TREX를 모두 활성화할 수 있습니다. 이 튜토리얼은 qiskit-ibm-runtime v0.50.0에서 도입된 Qiskit SamplerV2 및 EstimatorV2 인터페이스의 클라이언트 측 구현을 사용합니다. 이러한 클라이언트 측 프리미티브는 전처리와 후처리의 대부분을 로컬에서 수행하고 실행은 Executor 프리미티브에 위임합니다. 프리미티브가 클라이언트 측에서 실행되면 더 높은 투명성, 디버깅 시 더 빠른 피드백, 더 세밀한 제어를 얻을 수 있습니다.

클라이언트 측 프리미티브는 기존 서버 측 프리미티브와 동일한 API를 구현합니다. 따라서 대개 import 문만 변경하면 클라이언트 측 프리미티브로 전환할 수 있습니다. INFO 수준 로깅을 활성화하여 클라이언트 측 전처리와 후처리의 진행 상황을 확인하세요.

4.4 실행 구간 확인​

게이트 트위링처럼 여러 구성의 회로를 제출하면, IBM Quantum Compute Service는 모든 회로 구성을 반드시 동시에 실행하지는 않습니다. 대신 구성들을 청크로 묶어 샷 루프마다 청크 하나를 실행합니다. 샷 루프는 양자 하드웨어에서 이루어지는 한 번의 실행 라운드로, 청크의 모든 회로를 요청한 샷 수만큼 실행합니다.

실제 QPU에 제출되는 모든 작업에는 하드웨어로 보낼 수 있는 펄스로의 변환 같은 고전적 전처리가 필요합니다. 이 전처리는 병렬로 처리할 수 있으므로, 서비스는 한 번에 여러 작업을 큐에서 꺼내 시작합니다. 그러나 QPU는 한 번에 하나의 작업 단위만 처리할 수 있습니다. 따라서 작업이 여러 청크를 생성하면 다른 사용자 작업의 청크와 번갈아 실행될 수 있고, 각 청크는 QPU에서 자기 차례를 기다려야 할 수 있습니다.

작업 결과 메타데이터에는 각 청크의 QPU 실행 타이밍이 보고됩니다. 다음 시각화는 작업의 청크 실행 사이에 큰 간격이 있는지 보여 줍니다. 간격이 실험에서 허용할 수 있는 범위보다 크다면 작업을 다시 실행하거나, 워크로드에 QPU 단독 접근 권한을 제공하는 session 실행 모드를 사용하는 것이 좋습니다.
