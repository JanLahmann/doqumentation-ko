ColibriTD의 QUICK-PDE

API 레퍼런스를 참조하세요

참고

IBM Quantum® Functions는 IBM Quantum Premium Plan, Flex Plan, On-Prem(IBM Quantum Platform API를 통한) Plan 사용자만 이용할 수 있는 베타 기능이에요. 베타 기능은 변경될 수 있어요.

개요​

여기에 소개된 편미분 방정식(PDE) 솔버는 당사의 Quantum Innovative Computing Kit(QUICK) 플랫폼(QUICK-PDE)의 일부이며, 양자 함수로 패키징되어 있어요. QUICK-PDE 함수를 사용하면 IBM Quantum QPU에서 도메인 특화 편미분 방정식을 풀 수 있어요. 이 함수는 ColibriTD의 H-DES 설명 논문에 기술된 알고리즘을 기반으로 해요. 이 알고리즘은 전산 유체 역학(CFD)과 재료 변형(MD)을 시작으로, 이제 1~3개 자산에 대한 옵션의 Black-Scholes 방정식을 이용한 정량적 금융까지 복잡한 다중 물리 문제를 해결할 수 있어요. 다른 사용 사례도 곧 추가될 예정이에요.

미분 방정식을 다루기 위해, 시험 해(trial solution)는 직교 함수의 선형 결합(일반적으로 체비쇼프 다항식, 더 구체적으로는 최대 2n2^n2n개이며 여기서 nnn은 함수를 인코딩하는 Qubit의 수)으로 인코딩되고, Variable Quantum Circuit(VQC)의 각도로 매개변수화돼요. Ansatz는 함수를 인코딩하는 상태를 생성하며, 이는 모든 점에서 함수를 평가할 수 있는 관측량(observable)의 조합으로 평가돼요. 그런 다음 미분 방정식이 인코딩된 손실 함수를 평가하고, 하이브리드 루프에서 각도를 미세 조정할 수 있어요(아래 그림 참조). 시험 해는 만족스러운 결과에 도달할 때까지 실제 해에 점점 더 가까워져요.

이 하이브리드 루프 외에도, 여러 최적화기를 함께 연결할 수도 있어요. 이는 전역 최적화기로 좋은 각도 집합을 찾은 다음, 더 세밀한 최적화기로 기울기(gradient)를 따라 최적의 인접 각도 집합을 찾고자 할 때 유용해요. 전산 유체 역학(CFD)의 경우 기본 최적화 순서가 최상의 결과를 제공하지만, 재료 변형(MD)의 경우 기본값도 좋은 결과를 제공하면서 문제별 이점을 위해 추가로 구성할 수 있어요.

함수의 각 변수에 대해 Qubit의 수를 지정한다는 점을 참고하세요(직접 실험해 볼 수 있어요). 동일한 회로 10개를 쌓고 하나의 큰 회로 전체에서 서로 다른 Qubit에 대해 동일한 관측량 10개를 평가함으로써, 노이즈 학습기 방법에 의존하여 CMA 최적화 과정 안에서 노이즈를 완화하거나 PSR 계산을 병렬화하고, 필요한 샷 수를 크게 줄일 수 있어요.

**압력이 없는 오일러 방정식(pressureless Euler equations)**은 다음과 같이 감쇠가 있는 압축성 비점성 유체 흐름을 모델링합니다:

Ansatz​

각 function을 인코딩하는 변분 양자 회로는 ansatz 인수로 선택해요.

  • HEA는 전역 관측량으로 측정하는 하드웨어 효율적 ansatz입니다. 가장 범용적인 선택지입니다.

  • BPM-LE(Barren Plateau Mitigation, Low Expressivity)는 barren plateau를 피하도록 설계된 ansatz로, 국소 관측량으로 측정합니다. 매개변수가 적고 회로가 얕아서 parameter-shift 기울기 비용을 포함한 최적화 비용이 낮게 유지됩니다.

  • BPM-HE(Barren Plateau Mitigation, High Expressivity)는 같은 구성 방식을 따르되 회로당 매개변수를 더 많이 사용하며, 표현력이 낮은 버전으로는 충분히 정확하게 표현할 수 없는 함수에 사용합니다.

변수당 큐비트 수와 회로 깊이는 계속 nb_qubits 및 depth 인수로 제어합니다.

옵티마이저 체인과 오차 지표​

옵티마이저는 optimizers 인수를 통해 단계(stage)의 리스트로 연결됩니다. 각 단계는 자체 방법, 최대 반복 횟수, 자체 shot 수를 정의하므로, 처음에는 저렴하고 노이즈가 많은 평가로 해(解) 공간을 탐색하고, 최적화가 수렴함에 따라 shot 수를 늘립니다. 일반적인 체인은 다음 요소로 구성됩니다.

  1. 하나 이상의 CMAES 단계(전역, 기울기 없음)로, 해 공간에서 적절한 영역을 찾아냅니다. 각 단계는 자체 shots, sigma0, popsize(모집단 크기, 즉 각 세대에서 평가하는 후보의 수)를 가집니다. sigma0 인수는 CMA-ES 탐색 분포의 초기 표준편차, 즉 초기 스텝 크기입니다. 값이 크면 회로 매개변수 공간을 넓게 탐색하고, 값이 작으면 지금까지 찾은 최적 후보 주변을 국소적으로 탐색합니다. 따라서 단계가 진행될수록 sigma0을 줄이면 탐색에서 정밀화로 전환됩니다.

  2. LS-TRF 단계(Least Squares - Trust Region Reflective)로, 이 영역을 탐색하여 최종 각도를 정밀화합니다. psr 없이는 LS-TRF가 유한 차분으로 비용 함수의 야코비안을 추정합니다. psr=True를 사용하면 야코비안을 parameter-shift rule(PSR)로 QPU에서 정확하게 계산합니다. PSR은 추가 회로가 필요하므로 계산 시간이 늘어나지만, 유한 차분보다 더 높은 정밀도를 얻을 수 있습니다.

이 페이지에서 사용하는 오차 지표는 샘플링된 점들에 대한 해와 기준 해 사이의 평균 제곱근 오차(RMSE)입니다. 이 함수는 평균 제곱 오차(MSE)와 최대 절대 편차도 함께 보고하며, 이는 H-DES 논문의 2.6절에 나오는 d2 및 d1 지표입니다.

함수 크기​

이 함수는 run의 function_size 인수로 설정하는 컴퓨팅 크기 "S", "M" 또는 "L"로 실행됩니다. 문제에 필요한 크기는 플랜의 한도에 따라 결정됩니다.

  • 모드(session mode는 크기 "L"이 필요합니다)

  • 총 반복 횟수, 즉 optimizers 체인의 모든 단계의 max_iter 합계

  • 작업당 최대 shot 수, 즉 단계들의 shot 중 가장 큰 값(작업당 100,000 shot을 초과하는 것은 지원되지 않습니다)

  • 최대 큐비트 수, 즉 가장 큰 함수의 큐비트 수

크기는 이 모든 값이 한도 내에 들어가는 가장 작은 크기입니다. 온보딩과 지원은 사용 중인 플랜에 따라 달라지며 계산에 포함되지 않습니다. 크기 "M"의 한도를 넘는 문제는 크기 "L"로 산정됩니다.

전달한 크기가 문제에 필요한 크기보다 작으면 작업이 오류 코드 4600으로 실패합니다. 더 크면 작업은 실행되며, 더 작은 크기를 사용할 수 있음을 알려 주기 위해 오류 코드 4601이 포함된 이벤트를 보고합니다.

def calculate_function_size(problem: Any, **kwargs: Any) -> Size:
    """Return the size ("S", "M" or "L") required to run the function."""
    metrics = _measure(problem, **kwargs)
    if _is_small(metrics):
        return "S"
    if _is_medium(metrics):
        return "M"
    return "L"

def _measure(problem: Any, **kwargs: Any) -> dict:
    """Reduce the problem to a dict of numbers that drives your resource usage."""
    args = (
        {**problem, **kwargs}
        if isinstance(problem, dict)
        else {**kwargs, "use_case": problem}
    )

    use_case = str(args.get("use_case") or "").upper()
    if use_case not in _DEFAULT:
        raise ValueError(
            f"cannot size use_case {args.get('use_case')!r}: expected one of {list(_DEFAULT)}"
        )

    mode = (
        "job"
        if args.get("run_local")
        else str(args.get("mode") or "job").lower()
    )
    if mode not in _MODES:
        raise ValueError(
            f"cannot size mode {args.get('mode')!r}: expected one of {list(_MODES)}"
        )

    optimizers = args.get("optimizers")
    if optimizers is None:
        optimizers = _DEFAULT[use_case]["optimizers"]
    if not isinstance(optimizers, (list, tuple)) or not optimizers:
        raise ValueError(
            "optimizers must be a non-empty list of (name, parameters) pairs"
        )
    iterations, shots = 0, 0
    for i, stage in enumerate(optimizers):
        if (
            not isinstance(stage, (list, tuple))
            or len(stage) != 2
            or not isinstance(stage[1], dict)
        ):
            raise ValueError(
                f"optimizers[{i}] must be a (name, parameters) pair"
            )
        options = {str(k).lower(): v for k, v in stage[1].items()}
        shot, max_iter = options.get("shot"), options.get("max_iter")
        if not shot or not max_iter:
            raise ValueError(
                f"optimizers[{i}] must give 'shot' and 'max_iter'"
            )
        iterations += int(max_iter)
        shots = max(shots, int(shot))
    if shots > _MAX_SHOTS:
        raise ValueError(
            f"shots per job ({shots}) exceeds the maximum of {_MAX_SHOTS}"
        )

    nb_qubits = args.get("nb_qubits")
    if nb_qubits is None:
        nb_qubits = _DEFAULT[use_case]["nb_qubits"]
    qubits = max(
        sum(int(q) for q in per_var.values())
        for per_var in nb_qubits.values()
    )

    return {
        "mode": mode,
        "iterations": iterations,
        "shots": shots,
        "qubits": qubits,
    }

def _is_small(metrics: dict) -> bool:
    """Determine if the metrics fit T-size 'S'."""
    return (
        metrics["mode"] != "session"
        and metrics["iterations"] <= _SMALL["iterations"]
        and metrics["shots"] <= _SMALL["shots"]
        and metrics["qubits"] <= _SMALL["qubits"]
    )

def _is_medium(metrics: dict) -> bool:
    """Determine if the metrics fit T-size 'M'."""
    return (
        metrics["mode"] != "session"
        and metrics["iterations"] <= _MEDIUM["iterations"]
        and metrics["shots"] <= _MEDIUM["shots"]
        and metrics["qubits"] <= _MEDIUM["qubits"]
    )

RMSE는 해와 기준 해 사이의 평균 제곱근 오차입니다(Euler 및 인장 시험 사례에서는 두 함수에 대해 합산합니다). Burgers, Euler, 인장 시험 사례에서는 샘플링된 점들에 대해 QPU에서 측정합니다. Black-Scholes 사례에서는 최종 시간과 해가 부과되는 경계를 제외한 영역 내부에서, 조밀한 격자(1개 자산은 축당 600점, 2개 자산은 80점, 3개 자산은 16점)에서 QPU에서 선택된 매개변수를 사용한 노이즈 없는 시뮬레이션으로 계산합니다. 고전 계산 시간은 하이브리드 루프의 고전 쪽에서 옵티마이저가 소비한 시간입니다. 대부분 쉽게 병렬화할 수 있는 격자 점 평가에서 비롯됩니다. QPU 시간은 최적화 작업에 대해 청구되는 양자 처리 시간입니다.

큐비트 수는 이전 버전보다 적습니다. 회로 바인딩 기능은 큐비트 수가 아니라 실행의 QPU 시간을 줄여 줍니다. 여러 회로를 병렬로 실행하여 큐비트 수를 늘리는 것도 여전히 가능하며, 이렇게 하면 필요한 QPU 시간이 더욱 줄어듭니다. 또한 새 버전의 함수는 더 많은 큐비트와 더 큰 문제로 확장할 여지를 남겨 둡니다.

이 실행들의 최적화 단계는 다음과 같이 설명됩니다.

  • popsize 인수는 CMAES의 각 세대에서 평가하는 후보의 수입니다.
  • CMAES 단계는 비용이 더 이상 개선되지 않으면 일찍 멈출 수 있습니다.
  • 비용 평가는 하나의 회로 매개변수 집합에 대해 해당 단계의 shot 수로 QPU에서 측정하여 비용 함수를 계산하는 것입니다.
  • CMAES 한 세대는 popsize번의 평가로 이루어지므로, CMAES의 반복은 세대 단위로 셉니다.
  • LS-TRF 반복은 여기서는 parameter-shift rule(PSR)을 사용하여 현재 점에서 비용 함수의 야코비안을 계산하고, 하나 이상의 시험 점에서 비용 함수를 평가합니다.
  • 야코비안에는 자체 회로(parameter-shift된 회로)가 필요하며, 이는 평가로 세지 않습니다. 따라서 야코비안의 수는 LS-TRF 반복 횟수와 같고, 일부 시험 점이 기각되기 때문에 평가 횟수는 반복 횟수보다 많습니다.

Black-Scholes 방정식(계량 금융)​

Black-Scholes 사용 사례는 자산 또는 자산들의 변동성과 옵션 행사가를 입력으로 받습니다. 변동성 σ=0.3\sigma = 0.3σ=0.3, 행사가 K=1.2K = 1.2K=1.2인 단일 자산의 경우 결과는 다음과 같습니다.

use_case = "BS_1A"

size = calculate_function_size(use_case, optimizers=optimizers)
print(size)

# Select the volatility & strike

job = quick.run(
    use_case=use_case,
    optimizers=optimizers,
    physical_parameters={"sigma": 0.3, "K": 1.2},
    function_size=size,
)

solution = job.result()

해를 해석적 가격과 비교하고, 샘플링된 점들에 대해 RMSE를 계산합니다(자산 가격은 S=1+xS = 1 + xS=1+x입니다).

from scipy.stats import norm

def black_scholes_call(t, S, sigma, K, T=1.0):
    tau = T - t
    d1 = (np.log(S / K) + 0.5 * sigma**2 * tau) / (sigma * np.sqrt(tau))
    d2 = d1 - sigma * np.sqrt(tau)
    return S * norm.cdf(d1) - K * norm.cdf(d2)

params = solution["arguments"].get("physical_parameters") or {
    "sigma": 0.15,
    "K": 1.4,
}
params = {k.lower(): v for k, v in params.items()}

t, x = np.meshgrid(
    solution["samples"]["x_0"], solution["samples"]["x_1"], indexing="ij"
)
S = 1 + x
reference = black_scholes_call(t, S, sigma=params["sigma"], K=params["k"])

F = np.asarray(solution["functions"]["F_0"])
rmse = np.sqrt(np.mean((F - reference) ** 2))
print(f"RMSE: {rmse:.4f}")
t_grid = np.asarray(solution["samples"]["x_0"])
x_grid = np.asarray(solution["samples"]["x_1"])

n_times = 5
indices = np.unique(
    np.linspace(0, len(t_grid) - 1, n_times).round().astype(int)
)
blues = ["#86b6ef", "#5598e7", "#2a78d6", "#1c5cab", "#0d366b"]
colors = [
    blues[i]
    for i in np.linspace(0, len(blues) - 1, len(indices)).round().astype(int)
]

fig, ax = plt.subplots(figsize=(8, 5))
for color, i in zip(colors, indices):
    ax.plot(
        x_grid,
        F[i],
        color=color,
        lw=2,
        marker="o",
        ms=4,
        label=f"t = {t_grid[i]:.2f}",
    )
    ax.plot(x_grid, reference[i], color=color, lw=1.5, ls="--")

ax.plot([], [], color="0.4", lw=2, marker="o", ms=4, label="Qiskit Function")
ax.plot([], [], color="0.4", lw=1.5, ls="--", label="Reference")

ax.set_title(f"Black-Scholes 1D : F(t, x)   (RMSE = {rmse:.4f})")
ax.set_xlabel("x")
ax.set_ylabel("F(t, x)")
