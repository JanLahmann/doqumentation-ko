IBM Quantum Compute Service

이 페이지에서 IBM Quantum® Compute Service의 최신 패키지 릴리스 요약 및 플랫폼 업데이트를 확인하세요.

September 2026​

  • 첫 번째 Nighthawk r2 QPU 출시 — Premium, Flex 및 Pay-As-You-Go Plan에서 이제 첫 번째 IBM Quantum Nighthawk r2 QPU이자 지금까지 가장 빠른 프로세서인 ibm_phoenix에 액세스할 수 있습니다. ibm_phoenix는 Heron의 충실도를 유지하면서 최대 25배 더 높은 처리량을 제공하는 고연결성, 사각 격자 구조의 120 프로그래머블 큐비트 장치입니다.

    이러한 성능 향상은 모든 프로그래머블 큐비트를 더 빠르고 완전하게 바닥 상태로 되돌리는 새로 도입된 독립적인 고속 리셋에서 비롯됩니다. 그 결과, 기본 반복 지연(repetition delay)이 1µs(이전에는 250µs)로 줄어들어 처리량이 초당 최대 회로 수(Max Circuits Per Second, MCPS) 100,000을 넘어섭니다. IBM이 규모, 품질, 속도의 지표에 걸쳐 양자 하드웨어 성능을 추적하는 방법에 대해 자세히 알아보려면 이 블로그를 참조하세요.

    향상된 속도와 연결성 덕분에 동일한 용량으로 더 많은 유용한 작업을 수행할 수 있으며, 가장 크고 까다로운 워크로드가 가장 큰 혜택을 받습니다. 이전에는 대규모로 실행하기에 비용이 너무 컸던 더 큰 실험, 더 넓은 매개변수 스윕, 그리고 여러 방법을 이제 일상적으로 실행할 수 있습니다.

    ibm_phoenix는 또한 차세대 양자 오류 정정 연구를 위해 설계되었습니다. 고속 리셋과 더불어, 오류 정정에 대한 실시간 제어를 위한 중간 회로 리셋(mid-circuit reset)과 동적 회로(dynamic circuits)를 지원합니다.

August 2026​

  • IBM Quantum Platform 업데이트 — 최근 IBM Quantum Platform 업데이트를 통해 작업 결과를 더 쉽게 이해할 수 있고, Composer에서 강력한 새로운 회로 설계 기능을 사용할 수 있으며, 사용량 한도에 대한 정보를 계속 확인할 수 있어 양자 작업에 더 집중할 수 있습니다.

    • 작업 결과 및 워크로드

      • 비트별 결과 보기 — 전체 상태가 아닌 비트별로 결과를 세분화하는 Sampler 측정 결과를 보는 새로운 방식입니다. 결과에 많은 서로 다른 상태가 포함될 때 측정 결과 보기의 대안으로 유용합니다.

      • Circuit timing chart(회로 타이밍 차트) — 회로 작업(게이트, 채널, 지속 시간)의 예약된 타임라인을 보여줍니다. Sampler 및 Executor 작업에 사용할 수 있습니다. 타이밍 데이터 검색 활성화가 필요합니다.

      • Chunk/span 실행 진단 패널 — 청크 및 스팬 수준의 실행 진단을 보여주는 작업 세부 정보의 새로운 패널입니다. 이 데이터의 의미와 작업 제출 시 활성화하는 방법은 Sampler input/output을 참조하세요.

      • 한눈에 보는 디바이스 교정 데이터 — 이제 작업 세부 정보에서 "View calibration history" 링크를 통해 제출 또는 실행 시점의 디바이스 교정 데이터를 확인할 수 있습니다.

      • Executor 결과 시각화 — 이제 작업 세부 정보 페이지에서 Executor 작업의 결과를 렌더링합니다. Executor에 대한 자세한 내용은 Directed execution model (beta) 가이드를 참조하세요.

      • 동적 회로가 이제 작업 세부 정보에 렌더링됩니다 — Composer의 OpenQASM 3.0 지원(아래에서 자세히 설명)에 힘입어, 이전에는 렌더링에 실패했던 회로(예: 동적 회로를 사용하는 회로)가 이제 작업 세부 정보 페이지에 올바르게 표시됩니다.

      • 히스토그램 개선 — 더 빠른 로딩, 더 부드러운 확대/축소, 특정 결과 범위를 좁혀볼 수 있는 새로운 선택 도구를 제공합니다.

      • 작업 결과의 qiskit-ibm-runtime 코드 스니펫 — ID로 작업을 검색할 수 있는 즉시 사용 가능한 코드입니다. Executor 작업의 경우 작업을 복제할 수 있는 추가 스니펫도 제공됩니다.

      • 워크로드 테이블에 사용자 지정 날짜 범위 필터가 추가되었습니다.

      • 워크로드 세부 정보 페이지에서 관련 리소스로 연결되는 클릭 가능한 인스턴스 이름 및 태그입니다.

      이러한 개선 사항을 확인하려면 Workloads 페이지에서 결과로 이동하세요.

    • Composer: OpenQASM v3.0 지원

      이제 Composer는 OpenQASM v3.0을 지원하며, 다음이 추가됩니다:

      • 게이트 수정자(gate modifiers) — ctrl, inv, pow 등입니다.

      • 루프(Loops) — for 및 while입니다.

      • 조건 로직(Conditional logic) — if/else입니다.

      • 박스 주석(Box annotations) — 회로의 섹션을 그룹화하고 레이블을 지정합니다.

      또한 대규모 회로에 대한 더 부드러운 렌더링과 대규모 회로에서 PNG 내보내기가 실패하던 문제에 대한 수정 사항도 포함되었습니다.

    이 새로운 업데이트를 확인하려면 Composer를 방문하세요.

    • 인스턴스 사용 한도

      • 사용 한도에 도달한 Premium 및 Open Plan 인스턴스는 이제 순환 사용 기간을 기준으로 액세스가 재개되는 정확한 날짜를 표시합니다.

    자세한 내용은 Instances 페이지를 참조하세요.

Qiskit Runtime 명칭 변경​

  • Qiskit Runtime 서비스가 이제 IBM Quantum Compute Service로 변경됩니다 — 이는 명칭 변경일 뿐이며 코드 변경이나 기존 애플리케이션 업데이트가 필요하지 않습니다. 사용자 인터페이스와 문서 전반에서 새로운 이름을 확인할 수 있습니다.

    역사적으로 _Qiskit Runtime_이라는 용어는 서로 관련이 있지만 별개인 세 가지 개념을 지칭하는 데 사용되었습니다.

    Qiskit 사용자가 자사의 양자 컴퓨터에서 워크로드를 실행하기를 원하는 모든 하드웨어 제공업체는 두 가지 제공업체별 구성 요소를 제공해야 합니다:

    • 사용자가 제공업체에 작업을 제출할 수 있게 해주는 Qiskit SDK 확장입니다. IBM의 경우, 이는 오픈 소스 qiskit-ibm-runtime 라이브러리입니다. 양자 컴퓨터와 직접 통신하는 대신 클라우드 API에 작업을 제출합니다.

    • 양자 컴퓨터 자체에서 실행되는 런타임 실행 환경입니다. 이 구성 요소는 Qiskit primitive를 이해하고, 이를 하드웨어별 작업으로 변환하여 양자 하드웨어에서 실행합니다. IBM의 경우, 이것이 IBM Qiskit Runtime입니다.

    이 두 구성 요소 사이에는 세 번째 요소, 즉 qiskit-ibm-runtime SDK로부터 작업을 받아 실행을 조율하는 관리형 클라우드 서비스가 있습니다. 이 서비스는 인증, 스케줄링, 대기열 관리, 워크로드 라우팅, 사용량 추적, 한도 및 분석과 같은 기능을 담당합니다. 이 서비스 자체가 Qiskit primitive를 처리하지는 않으며, 대신 적절한 양자 컴퓨터로 워크로드를 전달하면 런타임 실행 환경이 실제 실행을 수행합니다.

    역사적으로 이 클라우드 서비스 역시 Qiskit Runtime Service라고 불렸는데, 이는 개념적으로 런타임 자체와는 다른 것입니다. 실행 환경과 관리형 클라우드 서비스 모두를 설명하는 데 Qiskit Runtime이라는 용어를 이중으로 사용하면서 — 아키텍처가 모호해지고 오픈 소스 구성 요소와 관리형 클라우드 제품을 구분하기 어려워졌습니다.

    Qiskit Runtime Service를 IBM Quantum Compute Service로 명칭을 변경하면 이러한 모호함이 해소됩니다. 그 결과 아키텍처가 훨씬 더 명확해집니다:

    • qiskit-ibm-runtime: 워크로드를 제출하는 오픈 소스 Qiskit 확장입니다.

    • IBM Quantum Compute Service: 워크로드를 인증, 스케줄링, 관리 및 라우팅하는 관리형 클라우드 서비스입니다.

    • IBM Qiskit Runtime(또는 IBM Qiskit Runtime 실행 환경): 양자 컴퓨터에서 실행되며 Qiskit primitive를 처리하고 실행하는 실행 환경입니다.

Store 명령어​

  • IBM® QPU에서 Store 명령어 지원 - 이제 Store 명령어를 사용하여 양자 회로에서 복잡한 고전 계산을 단순화할 수 있습니다.

    • 회로 중간에 고전 표현식을 계산하고 그 결과를 변수 또는 레지스터에 저장하면, 이후 즉시 후속 양자 게이트를 제어할 수 있습니다. 깊게 중첩된 인라인 표현식 대신, 계산을 명명된 중간 단계로 나눌 수 있어 복잡한 고전 피드백 로직을 더 쉽게 읽고 유지 관리할 수 있습니다. 일반적인 사용 사례는 다음과 같습니다:

      • 중간 측정과 고전 피드백이 있는 동적 회로

      • 장거리 얽힘 준비

      • 측정 결과를 기반으로 한 복잡한 조건 로직

      Store 명령어를 사용하려면 먼저 최신 버전의 qiskit-ibm-runtime을 실행하고 있는지 확인한 다음(pip install --upgrade qiskit-ibm-runtime), 자세한 정보와 예제는 문서를 참조하세요.

      작업을 제출하기 전에 문서에서 각 primitive의 옵션과의 호환성을 확인해야 합니다: Sampler 옵션 | Estimator 옵션 | Executor 옵션

    Qiskit Code Assistant 서비스의 예정된 중단​

    2026년 5월 29일, IBM Quantum은 프리뷰 상태인 Qiskit Code Assistant 서비스를 중단하고 Visual Studio Code 및 JupyterLab용 지원 확장 프로그램을 보관 처리할 예정입니다.

    피드백과 사용 패턴을 바탕으로 볼 때, 점점 더 많은 사용자가 Qiskit Code Assistant 모델을 로컬에서 실행하고 이미 개발 워크플로우의 일부인 에디터 통합 환경에서 작업하고 있습니다.

    Qiskit Code Assistant 모델은 로컬 사용을 위해 계속 제공됩니다. 계속 사용하려면 로컬 배포와 커뮤니티 지원 에디터 통합 또는 기타 로컬 도구로 전환하세요.

    설정 안내는 Qiskit Code Assistant 가이드를 참조하세요.

    Nighthawk가 EU에 도입됩니다​

    이제 Premium 및 Flex Plans는 ibm_berlin에 조기 액세스할 수 있습니다! 이는 EU(eu-de 리전)에서 최초로 도입된 IBM Quantum Nighthawk r1 QPU이며, 미국(us-east 리전)의 ibm_miami에 이어 전 세계 시스템 중 두 번째 Nighthawk입니다. ibm_berlin은 유사한 업계 최고 수준의 코히어런스(T1_11​ ~350 µs)를 유지하면서 ibm_miami보다 더 빠른 2-큐비트 게이트(중앙값 68 ns 대 138 ns)를 제공합니다.

    출시 이후 Nighthawk는 고전 시뮬레이션이 점점 더 어려워지는 영역에서 연구를 가능하게 해왔습니다. 특히, 이 아키텍처는 격자(lattice) 기반 모델에 자연스럽게 매핑되는 하드웨어 효율적인 워크플로우를 지원합니다. Nighthawk에서 대규모로 시뮬레이션을 수행한 Phasecraft 및 Volkswagen과 그 협력자들의 최근 논문을 참조하세요.

    ibm_berlin은 현재 지속적인 학습 주기의 일환으로 여전히 테스트 및 최적화 중인 탐색적 QPU입니다. 따라서 다음과 같은 제한 사항이 일시적으로 적용됩니다:

    • 기본 반복 시간이 250 µs에서 4 ms로 일시적으로 늘어났으며, 이는 워크로드 실행에 필요한 QPU 시간에 영향을 미칩니다. 사용자는 더 짧은 반복 시간을 수동으로 선택할 수 있지만 성능이 저하될 수 있습니다.

    • 동적 회로는 아직 지원되지 않으며, 중간 측정의 품질이 제한됩니다.

최대 반복 지연 시간 증가​

사용자에게 더 많은 유연성을 제공하기 위해, Heron 및 Eagle QPU에서 허용되는 반복 지연 시간 범위를 20-500 µs에서 20-2000 µs로 확장했습니다. Nighthawk QPU의 지연 시간 범위는 이전에 발표한 대로 1000-4000 µs로 유지됩니다. 반복 지연(rep_delay)을 늘리도록 선택하면 실행 시간과 용량 소비에 직접적인 영향을 미치지만, 특정 회로의 충실도(fidelity)가 향상될 수 있습니다. 기본 rep_delay는 모든 QPU에서 변경되지 않았습니다.

반복 지연 시간을 변경하는 방법을 포함한 자세한 정보는 Qubit initialization에서 확인할 수 있습니다.

두 번째 세션에서는 Qiskit Functions 카탈로그에 새롭게 추가된 세 가지 혁신적인 Qiskit Functions의 출시를 다룹니다. 각 함수 제공업체는 고유한 기능, 사용 사례, 더 넓은 생태계에 미치는 영향을 강조하며 자사의 솔루션을 발표합니다. 참석자들은 이러한 Qiskit Functions를 실제 애플리케이션에 활용하는 방법에 대한 직접적인 통찰을 얻을 수 있습니다.

2025년 2월 26일​

  • 오늘, 저희는 업그레이드된 경험의 얼리 액세스 버전을 출시하며, 계정을 만들고 새로운 인터페이스를 살펴보시기 바랍니다. 앞으로 몇 달 동안 계속해서 업데이트를 출시할 예정이며, 최종 목표는 IBM Quantum Platform Classic 버전과 같은 모습과 느낌을 가지면서도 더 뛰어난 기능을 제공하는 경험을 만드는 것입니다. 저희는 결국 IBM Quantum Platform Classic을 서비스 종료할 예정이니, 업데이트 소식을 계속 지켜봐 주세요.

  • 참고: IBM Quantum Platform 액세스가 플랜 관리자(Premium Plan, On-Prem Plan, Startup Program 등)에 속해 있는 경우, 앞으로 몇 달 동안 관리자를 통해 안내받는 마이그레이션 지원을 받게 됩니다. 그동안 새로운 플랫폼을 살펴보고 싶으시면 무료 Open Plan 계정을 만들어 이용해 보실 수 있습니다.

  • 얼리 액세스 릴리스 및 향후 개선 사항에 대한 자세한 내용은 블로그를 확인하세요.

2025년 2월 24일​

저희 인벤토리가 새롭게 개편되고 있으며, 2025년 4월 18일경에 다음 QPU들이 사용 중지될 예정입니다.

이 QPU들이 사용 중지되기 전에 중요한 과거 작업의 작업 데이터를 반드시 검색해 두세요.

2025년 2월 3일​

  • 모든 IBM Quantum 프로세서에서 펄스 수준 제어가 제거되었습니다. 또한 펄스 모듈은 Qiskit SDK v2.0에서 제거될 예정입니다. 대신, 이제 명령어 집합 아키텍처(ISA)에 내장된 프랙셔널 게이트(fractional gates)를 사용할 수 있습니다. 자세한 내용과 코드 마이그레이션 도움말은 Qiskit Pulse에서 프랙셔널 게이트로 마이그레이션을 참조하세요.

2025년 2월 2일​

  • 2025년 6월 2일부터 연중 계속해서 IBM Quantum은 동적 회로에 새로운 기능을 점진적으로 도입하여 유틸리티 규모에서 이를 사용할 수 있도록 할 예정입니다. 개선 사항은 다음과 같습니다.

    • Gen3 엔진 스택을 사용한 75배 실행 속도 향상

    • 회로 지속 시간을 줄이고 결과 품질을 향상시키는 분기의 병렬 실행

    • 회로 중간 측정(mid-circuit measurement)의 개선

    • 동적 디커플링과의 향상된 통합

    • 회로 타이밍 정보에 대한 향상된 가시성

  • 롤아웃을 가속화하기 위해 다음 기능은 더 이상 사용되지 않으며 2025년 6월 2일경에 지원이 중단됩니다:

    • while, for, switch 제어 흐름 구문

    • 분기 본문 내에서 제어 흐름 명령을 사용하는 기능(즉, 중첩된 제어 흐름)

    • 조건부 측정

2025년 1월 7일​

  • Gen3 엔진 스택의 롤아웃이 오늘부터 시작됩니다. 이 엔진 스택은 실행 속도를 75배 향상시킵니다. 롤아웃은 한 번에 하나의 QPU에서 진행되며, 해당 QPU의 일부 작업이 Gen3 경로를 사용하게 됩니다. gen3-turbo 실험적 옵션을 사용하여 Gen3 경로를 강제로 사용할 수도 있습니다. 이 엔진 스택은 fractional gate, pulse gate 또는 동적 회로와 호환되지 않는다는 점에 유의하세요.

2024년 8월 15일​

  • 확률적 오류 증폭(PEA) 오류 완화 방법을 이제 Estimator V2에서 사용할 수 있습니다. 자세한 내용은 ZneOptions API 참조를 참조하세요.

  • 새로운 헬퍼 프로그램 noise-learner를 이제 사용할 수 있습니다. 이를 통해 Pauli-Lindblad 노이즈 모델을 기반으로 관심 있는 하나 이상의 회로에서 gate에 영향을 미치는 노이즈 프로세스를 특성화할 수 있습니다. 출력된 노이즈 모델은 layer_noise_model 옵션을 통해 Estimator에 전달할 수 있습니다.

  • V1 primitives는 더 이상 지원되지 않습니다.

2024년 7월 3일​

  • 다음 엔드포인트는 더 이상 사용되지 않으며 2024년 10월 3일 이후 제거됩니다: GET /stream/jobs 및 GET /stream/jobs/{id}. 이 제거는 다음과 같은 영향을 미칩니다:

    • 엔드포인트가 제거된 후에는 job.stream_results() 및 job.interim_results()가 qiskit-ibm-runtime 클라이언트에서 제거됩니다.

    • 추가 메서드(예: job.result())는 현재 더 이상 사용되지 않는 엔드포인트를 사용합니다. 엔드포인트가 제거되기 전에 qiskit_ibm_runtime 0.25 이상으로 업그레이드하여 중단을 방지하세요.
