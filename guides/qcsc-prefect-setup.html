Slurm 클러스터에 QCSC-Prefect 설정하기

이 가이드는 Slurm 클러스터의 로그인 노드를 qcsc-prefect의 워크플로 호스트로 준비합니다. qcsc-prefect SQD 튜토리얼은 이 가이드의 결과에서 시작합니다.

이 가이드를 완료하면 다음 항목이 준비됩니다.

항목위치내용
~/venv/qcsc-host로그인 노드, 워크플로 호스트Prefect, qcsc-prefect 패키지, qcsc-qrmi 명령
~/venv/qcsc-node컴퓨트 노드, Slurm 작업 내부QRMI 워커: task_runner 명령이 포함된 QRMI와 qcsc-prefect-qiskit
qrmi-runtimePrefectIBM Quantum® 인스턴스와 QPU를 지정하는 블록
qrmi_config.json로그인 노드와 컴퓨트 노드QRMI용 IBM Cloud® API 키, 인스턴스, 백엔드

단계에서 달리 안내하지 않는 한, 각 명령은 로그인 노드의 터미널에서 실행하세요.

사전 요구 사항​

  • OpenMPI, PMIx, QRMI SPANK 플러그인이 설치된 Slurm 클러스터. 클러스터 관리자가 설치합니다. 다음 가이드에서 이러한 구성 요소를 설명합니다.

    • Quantum resource management interface (QRMI)

    • QRMI용 SPANK 플러그인

    • SPANK 플러그인 사용자 가이드

  • 로그인 노드와 컴퓨트 노드에서 동일한 절대 경로로 보이는 홈 디렉터리와 작업 디렉터리

  • 로그인 노드에서 GitHub, PyPI, IBM Quantum, Prefect Cloud로의 아웃바운드 HTTPS 접근, 그리고 컴퓨트 노드에서 IBM Quantum으로의 아웃바운드 HTTPS 접근

  • IBM Cloud API 키와 인스턴스가 하나 이상 있는 IBM Quantum Platform 계정

  • Prefect Cloud 계정 또는 직접 호스팅하는 Prefect 서버

  • 튜토리얼의 솔버 빌드를 위해 클러스터에 설치된 Git, C 및 C++ 컴파일러, CMake, BLAS, LAPACK, MPI

참고

예제에서는 Slurm 파티션 normal과 컴퓨트 노드 c1, c2를 사용합니다. 이를 사용 중인 클러스터의 이름으로 바꾸세요.

1단계: 로그인 노드에 로그인하기​

# Run in a terminal on your computer.
ssh <user>@<login-node>

2단계: uv 설치하기​

uv 패키지 관리자를 설치하고 설치를 확인하세요.

curl -LsSf https://astral.sh/uv/install.sh | sh
source "$HOME/.local/bin/env"
uv --version

3단계: 경로를 설정하고 작업 디렉터리 만들기​

이 가이드와 튜토리얼은 두 개의 환경 변수를 사용합니다.

변수예시용도
QCSC_PREFECT$HOME/qcsc-prefectqcsc-prefect 체크아웃
QCSC_WORK_DIR/shared/work/qcsc-prefect솔버 작업과 QRMI 작업의 작업 디렉터리

두 경로 모두 컴퓨트 노드에서 동일한 절대 경로로 보이는 스토리지에 있어야 합니다. 클러스터에 /shared 디렉터리가 없다면 다른 공유 경로를 선택하세요.

변수를 설정하고 작업 디렉터리를 만드세요. 튜토리얼을 따라 하기 전에 새 셸을 열 때마다 변수를 다시 설정하세요.

export QCSC_PREFECT="$HOME/qcsc-prefect"
export QCSC_WORK_DIR=/shared/work/qcsc-prefect
mkdir -p "$QCSC_WORK_DIR"

새 셸마다 변수를 자동으로 설정하려면 ~/.bashrc에 추가하세요.

# Optional
echo "export QCSC_PREFECT=$QCSC_PREFECT" >> ~/.bashrc
echo "export QCSC_WORK_DIR=$QCSC_WORK_DIR" >> ~/.bashrc

4단계: qcsc-prefect 복제하기​

저장소를 복제하고 릴리스 태그(예: v0.3.1)를 체크아웃하세요.

git clone https://github.com/qiskit-community/qcsc-prefect.git "$QCSC_PREFECT"
cd "$QCSC_PREFECT"
git checkout v0.3.1

5단계: 워크플로 환경 만들기​

Python 3.12로 워크플로 환경을 만들고 활성화하세요.

uv venv ~/venv/qcsc-host -p 3.12
source ~/venv/qcsc-host/bin/activate

qcsc-prefect 패키지를 설치하세요. --no-deps 옵션은 체크아웃된 패키지 간의 정확한 버전 고정을 유지합니다. 워크플로 자체는 튜토리얼에서 설치합니다.

cd "$QCSC_PREFECT"
uv pip install --no-deps \
  -e packages/qcsc-prefect-core -e packages/qcsc-prefect-adapters \
  -e packages/qcsc-prefect-blocks -e packages/qcsc-prefect-executor \
  -e 'packages/qcsc-prefect-qiskit[slurm]'

명령을 사용할 수 있는지 확인하세요.

which prefect qcsc-qrmi

로그인 노드에서 새 셸을 열 때마다 ~/venv/qcsc-host를 활성화하세요.

6단계: Prefect에 로그인하기​

Prefect Cloud에 로그인하세요. Paste an API key를 선택하고 Prefect Cloud API 키를 붙여넣은 다음 워크스페이스를 선택하세요.

prefect cloud login

연결을 확인하세요. 출력에 PREFECT_API_URL과 워크스페이스가 표시됩니다.

prefect config view
선택 사항: 자체 Prefect 서버 사용

Prefect Cloud를 사용한다면 이 참고는 건너뛰세요. Prefect Cloud 대신 자체 Prefect 서버를 사용하려면 Slurm 로그인 노드에서 Prefect 서버를 실행하고 접근하는 방법을 따르고, <server-host> 대신 서버 주소를 설정하세요.

# Optional: only for your own Prefect server
prefect config set PREFECT_API_URL=http://<server-host>:4200/api

7단계: IBM Quantum 자격 증명 저장하기​

qrmi-runtime 블록을 저장하므로 Prefect 로그인 후에 qcsc-qrmi login을 실행하세요.

qcsc-qrmi login

프롬프트에 답하세요.

  1. IBM Cloud API 키를 붙여넣으세요. 키는 표시되지 않습니다.

  2. 모든 인스턴스를 사용하려면 Enter를 누르세요.

  3. 기본 인스턴스의 번호를 입력하세요. 다음 예제에서는 1입니다.

  4. 기본 백엔드의 번호 또는 이름을 입력하세요. 다음 예제에서는 4(ibm_kingston)입니다.

이 명령은 컴퓨트 노드에 관한 참고와 sqd_blocks.toml용 [qrmi] 줄도 출력하지만, 예제에서는 생략했습니다(...). 워크플로가 qrmi-runtime 블록에서 인스턴스와 백엔드를 읽으므로 [qrmi] 줄은 필요하지 않습니다.

qcsc-qrmi 명령에는 다음 하위 명령이 있습니다.

명령용도
qcsc-qrmi loginAPI 키, 인스턴스, 백엔드를 저장하고 블록을 저장합니다
qcsc-qrmi refresh저장된 키로 인스턴스와 백엔드를 다시 찾습니다
qcsc-qrmi list키를 제외하고 인스턴스와 백엔드를 출력합니다
qcsc-qrmi check블록의 인스턴스가 해당 백엔드를 사용할 수 있는지 확인합니다

컴퓨트 노드에 파일 설치하기​

SPANK 플러그인은 각 컴퓨트 노드에서 plugstack.conf에 지정된 경로(주로 /etc/slurm/qrmi_config.json)의 qrmi_config.json을 읽습니다. 클러스터 관리자에게 ~/.qiskit/qrmi_config.json을 해당 경로에 설치해 달라고 요청하세요. qcsc-qrmi login 또는 qcsc-qrmi refresh를 실행할 때마다 다시 설치하세요.

SPANK 플러그인이 batch mode로 QPU를 획득하므로 qrmi-runtime 블록의 Session Mode를 batch로 유지하세요.

8단계: 컴퓨트 노드 환경 만들기​

QRMI 워커는 컴퓨트 노드에서 자체 환경으로 실행됩니다. 동일한 체크아웃에서 만드세요. --python 옵션은 ~/venv/qcsc-host를 활성 상태로 유지합니다.

cd "$QCSC_PREFECT"
uv venv ~/venv/qcsc-node -p 3.12
uv pip install --python ~/venv/qcsc-node/bin/python "qrmi[ibm]"
uv pip install --python ~/venv/qcsc-node/bin/python -e packages/qcsc-prefect-qiskit

qrmi[ibm] 패키지는 task_runner 명령을 제공합니다. 튜토리얼에서는 이 환경에 SQD 컴파일 훅을 추가하고, ~/venv/qcsc-node/bin/python을 sqd_blocks.toml의 python_executable로 사용합니다.

저장된 인스턴스와 백엔드를 확인하세요. 이 명령은 키를 출력하지 않습니다.

qcsc-qrmi list
# Output
API key: set
premium-instance (premium, us-east) (default): ibm_boston, ibm_chicago, ibm_fez, ibm_kingston, ibm_marrakesh, ibm_phoenix, ibm_pittsburgh

기본 인스턴스가 기본 백엔드를 사용할 수 있는지 확인하세요.

qcsc-qrmi check
# Output
premium-instance (premium, us-east) can use ibm_kingston.

Slurm이 PMIx를 포함하여 두 컴퓨트 노드 모두에서 작업을 실행하는지 확인하세요.

srun -N2 hostname
srun -N2 --mpi=pmix hostname
# Output of each command
c1
c2

컴퓨트 노드에서 컴퓨트 노드 환경과 작업 디렉터리를 확인하세요. 임포트가 성공하면 첫 번째 명령은 아무것도 출력하지 않습니다.

srun -N1 ~/venv/qcsc-node/bin/python -c "import qrmi, qcsc_prefect.integrations.qiskit.qrmi.worker"
srun -N1 ls ~/venv/qcsc-node/bin/task_runner
srun -N1 ls -ld "$QCSC_WORK_DIR"
