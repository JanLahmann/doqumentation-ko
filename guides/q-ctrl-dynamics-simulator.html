Dynamics Simulator - Q-CTRL Fire Opal의 Qiskit Function

API 레퍼런스를 참조하세요.

참고

Qiskit Functions는 IBM Quantum® Premium Plan, Flex Plan, On-Prem(IBM Quantum Platform API를 통한) Plan 사용자에게만 제공되는 실험적 기능입니다. 미리 보기 릴리스 상태이며 변경될 수 있습니다.

개요​

Q-CTRL Dynamics Simulator는 지원되는 양자 다체 모델의 시간 발전을 IBM Quantum 하드웨어에서 시뮬레이션하기 위한 애플리케이션 Qiskit Function입니다. 양자 회로를 직접 구성하는 대신 물리 모델, 초기 상태, 시간 발전 파라미터, 측정할 관측값을 지정합니다.

이 함수는 필요한 동적 회로를 구성하고 실행하며 Fire Opal의 하드웨어 인식 최적화 및 오류 억제 워크플로를 적용합니다. 결과는 요청한 관측값의 기댓값에 대한 시간 추이입니다. 이 함수는 오류 억제를 자동으로 적용하므로 기록적인 깊이의 회로를 실행하면서도 의미 있는 신호를 확인할 수 있습니다. Dynamics Simulator는 기존 최첨단 고전 도구와 일치하는 해의 정확도를 제공하며 속도 면에서 입증 가능한 이점을 제공합니다.

실제 환경 테스트에서 최고 해상도의 고전 텐서 네트워크 시뮬레이션과 비교했을 때 평균 제곱근 오차(RMSE) 1% 이내의 일치를 달성했습니다. 연구 커뮤니티의 독립적인 테스트는 양자 컴퓨터가 Q-CTRL의 초기 시연을 넘어서도 정확성을 유지한다는 것을 검증했습니다.

벤치마크​

사이트 수는 필요한 큐비트 수를 결정하고, Trotter 단계 수는 시간 발전 회로의 깊이를 제어합니다. 각 격자 사이트는 스핀 업과 스핀 다운 점유를 나타내기 위해 두 개의 큐비트를 사용합니다.

이 워크플로는 Trotter 단계 30개로 60개 사이트(120큐비트)의 체인, 그리고 Trotter 단계 90개로 31개 사이트(62큐비트)의 체인에 대해 시연되었습니다. 아래 표는 회로당 20,000 shot으로 IBM® Heron r3(ibm_boston) 장치에서 수행된 보고된 실험의 회로 리소스와 QPU 실행 시간을 보여 줍니다.

여기서 QPU 시간은 주요 시뮬레이션 회로의 누적 하드웨어 실행 시간입니다. 마지막 열에는 판독 오류 완화(REM)와 붕괴 복구(DR)에 사용되는 노이즈 특성화의 QPU 시간도 포함됩니다. 이 가이드는 작은 1차원 Fermi-Hubbard 예제를 사용하여 모델 정의부터 측정된 동역학 플로팅까지의 전체 워크플로를 보여 줍니다.

함수 설명​

양자 동역학은 양자 시스템이 시간에 따라 어떻게 변하는지를 설명합니다. 이러한 발전을 연구하면 입자가 어떻게 움직이는지, 상관관계가 어떻게 발전하는지, 그리고 시스템이 상태나 해밀토니언의 변화에 어떻게 반응하는지 이해하는 데 도움이 됩니다.

Fermi-Hubbard 모델은 격자 사이트 사이를 이동하며 같은 사이트를 차지할 때 상호작용하는 페르미온을 설명합니다. 호핑과 상호작용 사이의 경쟁 때문에 강하게 상관된 전자를 연구하는 데 유용한 모델입니다. 이 모델의 시간 발전은 스핀과 전하가 어떻게 전파되는지, 그리고 처음에 정렬된 시스템이 어떻게 이완되는지를 보여 줄 수 있습니다.

모델​

Dynamics Simulator는 열린 경계를 가진 1차원 Fermi-Hubbard 체인을 지원합니다. LLL개 사이트의 체인에 대해 해밀토니언은 다음과 같이 정의됩니다.

H=−∑i=0L−2∑σ∈{↑,↓}th,i(ciσ†ci+1,σ+ci+1,σ†ciσ)+∑i=0L−1Uini↑ni↓−∑i=0L−1∑σ∈{↑,↓}μiniσ.H = -\sum_{i=0}^{L-2}\sum_{\sigma\in\{\uparrow,\downarrow\}} t_{h,i} \left( c^\dagger_{i\sigma}c_{i+1,\sigma} + c^\dagger_{i+1,\sigma}c_{i\sigma} \right) +\sum_{i=0}^{L-1}U_i n_{i\uparrow}n_{i\downarrow} -\sum_{i=0}^{L-1}\sum_{\sigma\in\{\uparrow,\downarrow\}} \mu_i n_{i\sigma}.H=−i=0∑L−2​σ∈{↑,↓}∑​th,i​(ciσ†​ci+1,σ​+ci+1,σ†​ciσ​)+i=0∑L−1​Ui​ni↑​ni↓​−i=0∑L−1​σ∈{↑,↓}∑​μi​niσ​.

여기서 ciσ†c^\dagger_{i\sigma}ciσ†​와 ciσc_{i\sigma}ciσ​는 사이트 iii에서 스핀 σ\sigmaσ를 가진 페르미온을 생성하고 소멸시킵니다. 수 연산자 niσ=ciσ†ciσn_{i\sigma}=c^\dagger_{i\sigma}c_{i\sigma}niσ​=ciσ†​ciσ​는 해당 스핀 궤도의 점유를 측정합니다.

모델 입력은 다음 계수를 지정합니다.

  • hopping_amplitude: 이웃한 사이트 iii와 i+1i+1i+1 사이의 호핑을 제어하는 th,it_{h,i}th,i​입니다.

  • on_site_interaction: 같은 사이트를 차지하는 스핀 업과 스핀 다운 페르미온 사이의 상호작용인 UiU_iUi​입니다.

  • chemical_potential: 해밀토니언에 음의 부호로 들어가는 국소 화학 퍼텐셜인 μi\mu_iμi​입니다.

체인 전체에 동일한 계수를 사용하려면 스칼라를 제공하고, 개별 결합이나 사이트에 계수를 지정하려면 리스트를 제공하세요.

ℏ=1\hbar=1ℏ=1인 단위에서 초기 상태는 다음과 같이 발전합니다.

∣ψ(t)⟩=e−iHt∣ψ(0)⟩.|\psi(t)\rangle=e^{-iHt}|\psi(0)\rangle.∣ψ(t)⟩=e−iHt∣ψ(0)⟩.

이 함수는 지정한 관측값의 기댓값을 연속된 시뮬레이션 시간마다 추정합니다.

워크플로​

이 함수의 워크플로는 다음 단계로 구성됩니다.

  1. 알고리즘 합성: 이 함수는 해밀토니언과 시뮬레이션 시간 설정을 사용하여 최적화된 Trotter-Suzuki 시퀀스를 구성하며, 시뮬레이션 정확도를 고려하면서 회로 깊이를 줄입니다.

  2. 하드웨어 인식 매핑: 이 함수는 선택한 IBM Quantum 백엔드의 큐비트 연결성과 오류 특성을 사용하여 회로를 매핑하고 라우팅합니다.

  3. 물리 계층 오류 억제: Fire Opal은 동적 디커플링과 펄스 수준 보정을 적용하여 하드웨어 실행 중 환경으로 인한 노이즈와 크로스토크를 억제합니다.

이 함수는 이러한 단계를 자동으로 관리하고 요청한 관측값의 기댓값을 시간에 따라 반환합니다.

함수 입력을 통해 물리적 문제와 시뮬레이션 설정을 정의합니다. 현재 인터페이스는 Trotter 시간 발전을 지원하며, time_step은 각 단계의 지속 시간을, step_count는 단계 수를 설정합니다.

자세한 내용은 Fire Opal dynamics simulator 개요와 simulate_dynamics API 레퍼런스를 참조하세요.

  5. 동역학을 플로팅합니다.

4. 동역학 시각화​

초기 상태에는 스핀 업 페르미온이 하나 있고 스핀 다운 페르미온은 없습니다. 따라서 이 상태의 발전은 단일 입자 부분 공간에 머무르며, 그 네 개의 기저 상태는 페르미온이 사이트 0, 1, 2, 3을 차지하는 경우에 해당합니다.

이 부분 공간에서 해밀토니언은 호핑 진폭 −th-t_h−th​로 이웃한 사이트를 연결합니다. 여기에 사용된 파라미터에서는 다음과 같습니다.

H1p=−th(0100101001010010).H_{\mathrm{1p}} = -t_h \begin{pmatrix} 0 & 1 & 0 & 0 \\ 1 & 0 & 1 & 0 \\ 0 & 1 & 0 & 1 \\ 0 & 0 & 1 & 0 \end{pmatrix}.H1p​=−th​​0100​1010​0101​0010​​.

NumPy로 이 행렬을 대각화하고 Dynamics Simulator가 반환한 것과 같은 시간에서 초기 상태를 발전시키세요. 각 상태 진폭의 제곱 크기는 해당 사이트의 스핀 업 점유를 나타냅니다.

이 계산은 정확한 해밀토니언 발전을 제공합니다. 하드웨어 추정값과 이 기준값 사이의 차이에는 유한한 Trotter 단계, 측정 통계, 잔여 하드웨어 오류가 포함될 수 있습니다.

times = np.arange(expectation_values.shape[1]) * simulation["time_step"]

# This reference is specific to a single spin-up fermion.
if (
    len(initial_state) != site_count
    or initial_state.count("u") != 1
    or initial_state.count("e") != site_count - 1
):
    raise ValueError(
        "This reference requires one spin-up fermion and otherwise empty sites."
    )

# Build the Hamiltonian in the single-particle subspace.
hamiltonian = -model["hopping_amplitude"] * (
    np.eye(site_count, k=1) + np.eye(site_count, k=-1)
)
hamiltonian -= model["chemical_potential"] * np.eye(site_count)

# The rightmost character of initial_state corresponds to site 0.
initial_amplitudes = np.zeros(site_count, dtype=complex)
initial_site = initial_state[::-1].index("u")
initial_amplitudes[initial_site] = 1.0

# Evolve the initial state in the Hamiltonian eigenbasis.
energies, eigenvectors = np.linalg.eigh(hamiltonian)
initial_coefficients = eigenvectors.conj().T @ initial_amplitudes

phases = np.exp(-1j * np.outer(energies, times))
states = eigenvectors @ (initial_coefficients[:, None] * phases)

ideal_expectation_values = np.abs(states) ** 2

사이트마다 하나의 패널을 플로팅하세요. 실선 곡선은 기록된 시간에서의 정확한 기준값을 나타내고, 마커는 Dynamics Simulator가 반환한 하드웨어 추정값을 나타냅니다.

t=0t=0t=0에서 정확한 스핀 업 점유는 사이트 0에서 1이고 다른 사이트에서는 0입니다. 시스템이 발전함에 따라 호핑이 체인 전체에 입자의 확률을 퍼뜨립니다. 사이트 1의 점유가 가장 먼저 증가하고, 이어서 사이트 2와 3의 점유가 증가합니다. 이 예제의 파라미터에서 마지막으로 기록된 시간은 t=1.6t=1.6t=1.6입니다. 사이트 0부터 3까지의 정확한 점유는 각각 약 0.026, 0.370, 0.392, 0.211입니다.

정확한 점유는 모든 시간에서 다음 식을 만족하며, 이는 입자 수 보존을 반영합니다.

∑i=03⟨ni↑(t)⟩=1\sum_{i=0}^{3}\langle n_{i\uparrow}(t)\rangle=1i=0∑3​⟨ni↑​(t)⟩=1

입자가 유한한 체인을 따라 발전하면서 개별 사이트의 점유는 오르내릴 수 있습니다.
