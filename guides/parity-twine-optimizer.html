Parity Twine Optimizer: ParityQC의 Qiskit Function

API 참조를 참조하세요

참고

Qiskit Functions는 IBM Quantum® Premium Plan, Flex Plan, On-Prem(IBM Quantum Platform API를 통한) Plan 사용자만 이용할 수 있는 실험적 기능입니다. 미리보기 릴리스 상태이며 변경될 수 있습니다.

개요​

Parity Twine Optimizer는 Parity Twine 방식을 사용하여 양자 컴퓨터로 최적화 문제를 해결할 수 있게 합니다. Parity Architecture를 기반으로 한 이 접근 방식은 ParityQC 컴파일러를 사용하여 장치 연결성을 고려하면서 양자 알고리즘 실행에 필요한 게이트 수와 회로 깊이를 최소화합니다.

이러한 리소스 절감을 통해 표준적이고 SWAP이 많은 트랜스파일 방법으로는 실행 불가능한 규모의 산업 관련 최적화 문제를 해결할 수 있습니다. Parity Twine Optimizer는 트랜스파일 단계를 자동화하며 최소한의 사용자 입력으로 사용할 수 있습니다.

Parity Twine 방식은 양자 근사 최적화 알고리즘(QAOA) 및 양자 푸리에 변환(QFT)과 같은 양자 알고리즘에 대해 게이트 수와 회로 깊이를 줄이는 측면에서 다른 모든 컴파일 방법을 능가합니다. 양자 정보를 물리적 큐비트로부터 추상화함으로써 비국소적 상호작용이 SWAP 게이트 없이 구현됩니다. 대신 Parity Twine 체인(CNOT 게이트 시퀀스)이 큐비트 간에 논리적 패리티 정보를 체계적으로 분배합니다.

이 최적화기는 QAOA를 사용하여 주어진 비용 함수의 에너지를 최소화합니다. QAOA는 비용 해밀토니안(HCH_CHC​)의 바닥 상태를 근사함으로써 조합 최적화 문제를 해결하도록 설계된 하이브리드 양자-고전 변분 알고리즘입니다. 믹싱 항(HBH_BHB​)은 상태 간 전이를 유도하여 솔루션 공간을 탐색합니다. 매개변수 γ\gammaγ와 β\betaβ로 제어되는 이 항들의 교대 시퀀스는 초기 상태에 작용하는 유니터리 U(γ,β)=Πi=1pe−iβiHBe−iγiHCU(\gamma, \beta) = \Pi_{i=1}^p e^{-i \beta_i H_B} e^{-i \gamma_i H_C}U(γ,β)=Πi=1p​e−iβi​HB​e−iγi​HC​를 정의합니다.

문제 유니터리 exp(−iβHC)-i \beta H_C)−iβHC​))의 인코딩은 모든 논리적 nnn체 회전 연산자(exp(−iβJi,j,...nZiZj...Zn-i \beta J_{i,j,...n}Z_iZ_j...Z_n−iβJi,j,...n​Zi​Zj​...Zn​))의 인코딩을 필요로 합니다. 이는 nnn체 생성자(Parity Twine 네트워크)를 사용하여 달성할 수 있으며, 이는 QAOA 회로 깊이와 2큐비트 게이트 수를 줄입니다.

설명​

Parity Twine Optimizer의 입력은 최적화 문제, 선택한 IBM Quantum 하드웨어 이름, 그리고 트랜스파일 및 하드웨어 실행 설정을 조정하기 위한 추가 선택적 인수로 구성됩니다. 최적화기 함수는 문제 정의를 Parity Twine 컴파일러로 라우팅합니다. 그림 1은 함수 워크플로의 요약을 보여줍니다.

입력 최적화 문제는 (정규화된) 해밀토니안으로 전처리됩니다. 그런 다음 ParityQC 컴파일러는 매개변수화된 Parity Twine 앤사츠 회로를 구성하며, 이는 선택한 하드웨어의 네이티브 게이트 세트에 맞는 논리적 앤사츠로 트랜스파일됩니다.

QAOA 회로 매개변수는 "efficient depth one" 접근 방식을 사용하여 고전적으로 최적화되고 트랜스파일된 회로에 할당됩니다. QAOA의 한 라운드만 사용되므로, 최적의 γ\gammaγ와 β\betaβ 매개변수는 많은 회로 호출에 대한 비용이 많이 드는 반복 최적화 없이 CPU에서의 그리드 검색을 사용하여 얻어집니다. 덕분에 최적화기에 필요한 QPU 실행 시간이 크게 줄어들어요. 회로당 실행 시간은 대부분 QPU에서 작업을 실행하는 데 드는 일정한 오버헤드에 의해 결정됩니다. 회로 매개변수가 설정되면 작업이 지정된 IBM® QPU로 제출됩니다.

그런 다음 원시 결과가 후처리됩니다. 이 단계는 솔루션 문자열의 비트를 무작위 순서로 훑으면서 비용 함수 값을 줄이는 경우 비트 값을 뒤집는 로컬 그리디 탐색을 사용합니다.

벤치마크​

면책 조항

성능은 문제 인스턴스와 이후 처리 단계 모두에 따라 달라질 수 있습니다. 경우에 따라 고전적 샘플과 양자 생성 샘플이 동등한 후처리 후 유사한 최종 솔루션 품질을 달성할 수 있습니다. 따라서 평가에는 전체 최적화 워크플로를 고려해야 합니다.

셰링턴-커크패트릭 모델​

그림 2는 Parity Twine Optimizer의 효과를 보여줍니다. 이는 큐비트 수가 증가하는 셰링턴-커크패트릭 모델에 대해 최적화기를 사용하여 얻은 결과를 무작위 샘플링과 비교합니다.

무작위 결과와 최적화기 결과 모두의 후처리는 정확한 바닥 상태로 이어지지만, Twine QAOA의 원시 최소 에너지 출력은 항상 무작위 값보다 좋습니다. 고려된 최대 큐비트 수(90 및 100)의 경우, 하드웨어 노이즈로 인해 최적화기 결과가 저하되어 무작위 샘플링과 일치하는 원시 값으로 되돌아갑니다.

셰링턴-커크패트릭 모델 소개와 Parity Twine Optimizer로 이를 해결하는 방법에 대한 자세한 내용은 이 튜토리얼을 참조하세요.

마켓 스플릿 문제​

표 1은 마켓 스플릿(MS) 문제의 다양한 인스턴스에 적용된 Parity Twine Optimizer의 구체적인 성능 지표를 보여줍니다. 이는 QOBLIB - 양자 최적화 벤치마킹 라이브러리에서 얻어졌으며 Parity Twine Optimizer를 사용하여 라이브러리에 제출된 제출물에 해당합니다.

MS 위반은 솔루션이 모든 제약을 만족시키는 것에서 얼마나 벗어났는지를 측정하는 정확도 지표로, ∑i((Ax−b)i)2\sum_i ((Ax - b)_i)^2∑i​((Ax−b)i​)2로 정의됩니다. 이 지표 값이 낮을수록 더 정확한 솔루션을 나타냅니다. 표 1은 ibm_boston 장치를 백엔드로 사용하고 100,000샷을 사용한 Parity Twine Optimizer로 각 인스턴스를 5회 실행한 평균값을 보고합니다. 각 인스턴스 실행에서 얻은 최소 MS 위반이 보고됩니다.

최대 독립 집합 문제​

그림 3은 QOBLIB - 양자 최적화 벤치마킹 라이브러리에서 얻은 선택된 인스턴스에 대해 최대 독립 집합 문제에 대해 Parity Twine 최적화기를 사용하여 얻은 결과를 무작위 샘플링과 비교합니다. 이는 18(mammalia-kangaroo-interactions)개부터 114(es60fst03)개까지의 큐비트 범위입니다.

작은 인스턴스의 경우 최적화기와 무작위 샘플링의 원시 최대 독립 집합 크기 결과는 유사하지만, 더 큰 인스턴스의 경우 최적화기가 훨씬 더 좋은 결과를 제공합니다. 무작위 샘플링 결과와 최적화기 결과 모두의 후처리는 다시 정확한 값과 일치하는 세트 크기로 이어집니다.

예제​

Parity Twine Optimizer는 다음과 같이 간단한 QUBO 예제에 적용할 수 있습니다. 문제는 먼저 딕셔너리를 사용하여 정의됩니다:

problem = {"()": 3, "(0,)": 1, "(0, 1)": 2, "(1, 2)": -1}

그런 다음 변수 유형을 binary 또는 spin으로 정의해야 합니다:

variable_type = "spin"

이는 si∈{−1,1}s_i \in \{-1, 1\}si​∈{−1,1}인 목적 함수 3+s0+2s0s1−s1s23 + s_0 + 2 s_0s_1 - s_1s_23+s0​+2s0​s1​−s1​s2​를 정의합니다.

백엔드를 선택합니다. 예를 들면:

backend_name = "ibm_phoenix"

사용자 계정/인스턴스에서 사용 가능한 백엔드 목록을 보려면 catalog.backends()를 사용하세요.

백엔드가 지정되지 않은 경우 가장 한가한 백엔드(대기 중인 작업 수가 가장 적은 백엔드)가 자동으로 선택됩니다.

최적화기가 로드되면(앞서 참조) 기본 옵션을 사용하여 문제에 대해 실행할 수 있습니다:

function_job = function.run(
    problem=problem, variable_type=variable_type, backend_name=backend_name
)
print(f"Job ID: {function_job.job_id}")

다음과 같이 작업 상태를 확인합니다:

# Monitor the job status
function_job.status()

다음과 같이 결과를 가져와요:

# Retrieve the job result if the status is DONE
result = function_job.result()

objective_value는 최적화 문제의 비용 또는 에너지입니다. 이는 solution의 품질을 정량화합니다.

결과 출력의 모든 비트스트링은 variable_mapping을 사용하여 문제 변수에 매핑될 수 있습니다. 예를 들어, 'solution_bitstring': '100'을 'variable_mapping': {'0': 0, '1': 1, '2': 2}를 사용하여 이진 솔루션 {'0': 1, '1': 0, '2': 0}에 매핑할 수 있습니다. 스핀 변수로 문제를 해결하고 있으므로 이진에서 스핀으로의 변환(0 -> 1, 1 -> -1)을 적용해야 합니다. 그러면 최종 솔루션 'solution': {'0': -1, '1': 1, '2': 1}에 도달합니다.

Parity Twine Optimizer 함수의 입력 및 출력에 대한 자세한 내용은 API 참조를 참조하세요.
